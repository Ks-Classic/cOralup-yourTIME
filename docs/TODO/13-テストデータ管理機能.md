# テストデータ管理機能

**作成日**: 2025-12-19

## 1. 背景

開発・テスト時にvisitを何度も作成するが、本番運用前にこれらを削除しないと：
- 集計データが汚染される
- ダッシュボードの統計が正確でなくなる
- ストレージ容量が無駄に消費される

## 2. 機能要件

### 2.1 テストデータ生成
管理画面からワンクリックで以下を生成：
- テスト用 `children` レコード（名前に [TEST] プレフィックス）
- テスト用 `visits` レコード（`is_test_data: true` フラグ付き）
- 問診回答のサンプルデータ（オプション）

### 2.2 Visitリセット
特定のvisitを選択して：
- ステータスを `waiting` / `questionnaire_started` に戻す
- 関連する診断回答・写真・レポートを削除（オプション）

### 2.3 テストデータ一括削除
本番運用前に：
- `is_test_data = true` の visits を一括削除
- 名前に [TEST] を含む children を一括削除
- 関連する responses, photos, reports も連鎖削除

## 3. 実装方針

### 3.1 データベース変更
```sql
-- visits テーブルにテストフラグ追加
ALTER TABLE visits ADD COLUMN is_test_data BOOLEAN DEFAULT FALSE;
```

### 3.2 API
- `POST /api/admin/test-data/generate` - テストデータ生成
- `POST /api/admin/test-data/reset-visit` - Visit リセット
- `DELETE /api/admin/test-data/cleanup` - テストデータ一括削除

### 3.3 UI
管理ダッシュボード (`/admin`) に「開発ツール」セクションを追加：
- 「テストデータ生成」ボタン
- 「Visitリセット」ダイアログ
- 「テストデータ削除」ボタン（確認ダイアログ付き）

## 4. 安全対策

1. **本番環境では非表示**: 環境変数で制御
2. **確認ダイアログ**: 削除前に「本当に削除しますか？」
3. **削除ログ**: 何を削除したかをline_message_logsなどに記録
4. **権限チェック**: admin ロールのみ実行可能
