# 20: 運用正本リファクタリング

**作成日**: 2026-06-29
**優先度**: P0
**目的**: DBに保存されたデータを正本にし、当日運用・レポート表示・後日集計が壊れない構造へ整理する。
**残リスク台帳**: [21-残リスク台帳と最高品質レビュー.md](./21-残リスク台帳と最高品質レビュー.md)

---

## 1. 結論

Lark Base 連携は廃止対象とする。

理由:
- レポート・集計・後日分析は、Postgresに正規化データが残っていれば再生成できる。
- 現行アプリの主要導線は Lark を参照していない。
- Lark同期は status 定義、参照テーブル、重複防止、エラー応答の面で現行設計と乖離している。
- 当日運用の正本はアプリ内管理画面と `/api/admin/realtime-status` に寄せる方が障害範囲が小さい。

## 2. 非交渉ルール

### 2.1 DB正本

| データ | 正本 |
|---|---|
| 来場/診断単位 | `visits.id` |
| 子供 | `children.id` |
| 親御さん/スタッフ | `profiles.id` |
| 問診回答 | `questionnaire_responses.visit_id` |
| 診断回答 | `diagnosis_responses.visit_id` |
| 写真 | `visit_photos.visit_id` |
| レポート | `reports.visit_id` |
| LINE送信ログ | `line_message_logs.visit_id` |

`sessionId` / `session_id` は QR、受付表示、電話サポート、ログ追跡の補助IDに限定する。

### 2.2 状態管理

`visits.status` はDB制約に合わせて以下のみ許可する。

| status | 意味 |
|---|---|
| `waiting` | LINE登録後、問診前 |
| `in_progress` | 問診中から診断中 |
| `completed` | 現場診断/分析/レポート生成まで完了 |
| `published` | レポートURLを保護者へ送信済み |
| `cancelled` | 中止 |

詳細工程は `visits.current_step` に保存する。

| current_step | 意味 |
|---|---|
| `line_registered` | LINE登録完了 |
| `questionnaire_started` | 問診開始 |
| `questionnaire_completed` | 問診完了、QR表示/スタッフ待ち |
| `diagnosis_started` | スタッフ診断開始 |
| `photos_uploaded` | 写真アップロード完了 |
| `analysis_completed` | AI分析完了 |
| `report_generated` | レポート生成完了 |
| `line_sent` | LINE送信完了 |
| `line_confirmed` | スタッフによる到達確認完了 |

`diagnosis_completed`、`report_sent`、`analysis_completed` を `status` に入れてはいけない。

### 2.3 レポートURL

現行実装に合わせ、公開URLは `/report/{visitId}` とする。

`reports.id` はレポート行の主キー、`reports.visit_id` は表示・再生成・再送の正本。
`reportUuid` / `reports.uuid` をURL正本とする古い設計は廃止する。
