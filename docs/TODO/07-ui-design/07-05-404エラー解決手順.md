# 404エラー解決手順とディレクトリ構造について

## 404エラーの解決方法

### 1. ビルドキャッシュのクリアと再起動（最重要）

```bash
# 開発サーバーを停止（Ctrl+C）

# ビルドキャッシュを削除
rm -rf .next

# 開発サーバーを再起動
pnpm dev
```

### 2. ブラウザのキャッシュクリア

- Chrome/Edge: `Ctrl+Shift+Delete` → キャッシュをクリア
- またはシークレットモード/プライベートモードでアクセス

### 3. 確認すべきURL

**親御さん向け:**
- `http://localhost:3000/parent` ✅
- `http://localhost:3000/parent/questionnaire/demo` ✅
- `http://localhost:3000/parent/result/demo` ✅

**スタッフ向け:**
- `http://localhost:3000/staff` ✅
- `http://localhost:3000/staff/diagnosis` ✅ (統合診断ページのエントリーポイント)
- `http://localhost:3000/staff/diagnosis/demo` ✅ (デモ用統合診断ページ)
- `http://localhost:3000/staff/diagnosis/[id]` ✅ (動的統合診断ページ)
- `http://localhost:3000/staff/session/demo` ✅ (セッション詳細デモ)
- `http://localhost:3000/staff/session/[id]` ✅ (セッション詳細)

## ディレクトリ構造について

### Route Groups `(parent)` と `(staff)` について

`(parent)` と `(staff)` は **Next.js App RouterのRoute Groups** という機能です。

**重要なポイント:**
- ✅ **URLパスには含まれません**（`()` で囲まれたディレクトリは無視される）
- ✅ **レイアウトを整理するための機能**
- ✅ **Next.jsの標準的な構造**

### 現在の構造

```
src/app/
├── (parent)/                    ← Route Group（URLパスに含まれない）
│   ├── layout.tsx              ← 親御さん用レイアウト
│   └── parent/                 ← 実際のURLパス `/parent`
│       ├── page.tsx           ← /parent
│       ├── questionnaire/
│       │   ├── [id]/page.tsx  ← /parent/questionnaire/[id]
│       │   └── demo/page.tsx  ← /parent/questionnaire/demo
│       └── result/
│           ├── [id]/page.tsx  ← /parent/result/[id]
│           └── demo/page.tsx  ← /parent/result/demo
│
└── (staff)/                    ← Route Group（URLパスに含まれない）
    ├── layout.tsx              ← スタッフ用レイアウト
    ├── staff/page.tsx         ← /staff
    ├── diagnosis/
    │   ├── page.tsx           ← /staff/diagnosis (統合診断ページのエントリーポイント)
    │   ├── [id]/page.tsx      ← /staff/diagnosis/[id] (統合診断ページ)
    │   └── demo/page.tsx      ← /staff/diagnosis/demo (デモ用統合診断ページ)
    ├── session/
    │   ├── [id]/page.tsx      ← /staff/session/[id]
    │   └── demo/page.tsx      ← /staff/session/demo
    └── settings/
        └── page.tsx           ← /staff/settings
```

### Route Groupsの利点

1. **レイアウトの整理**: 異なるユーザータイプごとにレイアウトを分けられる
2. **URLパスの簡潔性**: URLは `/parent`, `/staff` のようにシンプルに保てる
3. **コードの整理**: 関連するページをグループ化できる

### もしRoute Groupsを削除する場合

Route Groupsを削除すると、以下のような構造になります：

```
src/app/
├── parent/
│   ├── page.tsx              ← /parent
│   └── questionnaire/
└── staff/
    ├── page.tsx              ← /staff
    └── diagnosis/
```

**問題点:**
- レイアウトを各ページで個別に管理する必要がある
- コードの重複が増える可能性
- レイアウトの変更が大変になる

## 推奨事項

**現在の構造（Route Groups使用）を維持することを推奨します。**

理由：
- ✅ Next.js App Routerの標準的な構造
- ✅ レイアウト管理が簡単
- ✅ URLパスはシンプル
- ✅ コードの整理がしやすい
