# Story: Lark Base リアルタイム同期設定

## 概要
Supabaseのvisitsテーブル変更をDB Trigger経由でLark Baseにリアルタイム同期する

## 含まれるタスク

### Phase 1: Edge Function準備
- [x] Edge Function実装 (`supabase/functions/lark-sync/index.ts`)
- [ ] Edge Functionデプロイ (`supabase functions deploy lark-sync`)
- [ ] Edge Function環境変数設定（Supabase Dashboard）

### Phase 2: DB Trigger設定
- [x] pg_net拡張有効化（マイグレーション済み）
- [x] notify_lark_sync()関数作成（マイグレーション済み）
- [x] visitsテーブルにTrigger設定（マイグレーション済み）
- [ ] Webhook URL設定 (`app.settings.lark_webhook_url`)

### Phase 3: Lark Base準備
- [ ] Lark Baseアプリ作成
- [ ] 来場者ログテーブル作成
- [ ] リアルタイム集計テーブル作成
- [ ] 異常検知アラートテーブル作成
- [ ] App Token / Table ID取得

### Phase 4: 環境変数設定
- [ ] `LARK_APP_ID` 設定
- [ ] `LARK_APP_SECRET` 設定
- [ ] `LARK_BASE_APP_TOKEN` 設定
- [ ] `LARK_BASE_TABLE_ID` 設定
- [ ] `LARK_STATS_TABLE_ID` 設定
- [ ] `LARK_ALERTS_TABLE_ID` 設定

### Phase 5: 動作確認
- [ ] visits INSERT時のLark同期確認
- [ ] visits UPDATE時のLark同期確認
- [ ] リアルタイム統計更新確認
- [ ] タイムアウトアラート確認

## 成功基準
- [ ] 診断完了時にLark Baseに即反映される
- [ ] ダッシュボードで本日の来場者数・待機人数がリアルタイム表示
- [ ] 30分以上待機でアラートが自動作成される

## 実装済みファイル
| ファイル | 説明 |
|---------|------|
| `supabase/functions/lark-sync/index.ts` | Lark同期Edge Function |
| `supabase/migrations/20241202000001_lark_webhook_trigger.sql` | DB Trigger定義 |

## データフロー
```
[UI] → [API Route] → [Supabase INSERT/UPDATE]
                              ↓
                    [DB Trigger: notify_lark_sync()]
                              ↓
                    [pg_net HTTP POST]
                              ↓
                    [Edge Function: lark-sync]
                              ↓
                    [Lark Base API]
```

## 備考
- クライアント（保護者/スタッフUI）はLark認証情報を一切持たない
- Edge FunctionはSupabase内部からのみ呼び出し（Webhook URL非公開）
- 同期失敗してもDBトランザクションは継続（非同期処理）
