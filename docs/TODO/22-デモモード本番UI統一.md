# 22: デモモード本番UI統一

**作成日**: 2026-06-29
**優先度**: P1
**目的**: スタッフ説明・練習・検証で使うデモモードを、本番診断画面と同じUI/操作体験に統一する。

---

## 1. 現状

本番診断画面とデモ診断画面が別ファイルで大きく重複している。

| 画面 | ファイル | 行数 | 問題 |
|---|---|---:|---|
| 本番 | `src/app/staff/diagnosis/[id]/page.tsx` | 約3012行 | 実DB/API/自動保存/レポート生成を持つ |
| デモ | `src/app/staff/diagnosis/demo/page.tsx` | 約2184行 | モック中心。UI・文言・レポート挙動が本番からズレる |

このままだと、本番UIを改善するたびにデモUIが古くなる。
スタッフ説明会でデモを触った体験と本番操作が異なると、当日の操作ミスにつながる。

---

## 2. 方針

**UIは1つ、データソースだけ切り替える。**

やらないこと:
- デモページに本番UIの変更を手作業でコピーし続ける
- 本番画面とデモ画面を別々にリファクタする
- デモ専用の見た目/操作を増やす

やること:
- `StaffDiagnosisExperience` のような共有コンポーネントを作る
- 本番ページは `mode="production"` と `visitId` を渡す
- デモページは `mode="demo"` とモックプロバイダを渡す
- ボタン、下部メニュー、レポート確認、LINE確認ダイアログは同じコンポーネントを使う

---

## 3. 目標UX

スタッフがデモで練習した内容が、そのまま本番で再現できる状態にする。

| 領域 | 本番 | デモ |
|---|---|---|
| 下部メニュー | 同じ | 同じ |
| 問診確認 | 実データ | 同じレイアウトのサンプルデータ |
| 写真撮影 | カメラ/アップロード | 同じUI、保存だけモック |
| 診断入力 | 実マスタ/API | 同じマスタ/APIまたは同型モック |
| AI分析 | 実API | 同じ画面遷移、結果だけ固定サンプル |
| レポート生成 | `/api/report/{visitId}/create` | 同じ表示、保存だけモック |
| LINE送信 | 親御さんへ実送信 | スタッフ本人へデモLINE実送信 |
| 完了確認 | 実DB更新 | 同じ完了UI、更新だけモック |

デモモードのDB方針:
- 診断スキーマなどの読み取りAPIは許容する。
- visit/report/LINE配信確認など、実運用データを変更する書き込みAPIは呼ばない。
- 写真、分析結果、完了状態は画面内stateまたはモックで完結させる。
- 例外として、ログイン中スタッフ本人へのLINE Push送信だけ許容する。送信先はスタッフセッションの `lineUserId` に限定し、患者/保護者の `lineUserId` や任意入力IDには送らない。
- デモLINE送信はスタッフ用LINEチャネルを使い、DBログ・visit更新・report作成を行わない専用APIに隔離する。
