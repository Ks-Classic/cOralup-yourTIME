# 05-02 Lark連携廃止

**更新日**: 2026-06-29
**優先度**: P0
**状態**: 🗑️ 廃止対象

---

## 概要

Lark Base連携は新規開発しない。
Supabase/PostgresをDB正本、アプリ内管理画面を当日運用正本とする。

このファイルは過去のLark連携案を廃止し、削除作業のチェックリストとして扱う。

---

## 廃止理由

- レポートはDBに `reports.visit_id` と関連データがあれば後から再表示・再送・再生成できる。
- 現行アプリの主要導線はLarkを参照していない。
- Lark同期実装は旧status、旧テーブル、重複防止不足を含み、当日運用の正本にするにはリスクが高い。
- 外部BIが必要になった場合も、DB正本から後処理で出力すればよい。

---

## 削除チェックリスト

- [ ] 新規環境で `20241202000001_lark_webhook_trigger.sql` を適用しない方針を明記する。
- [x] 既存DB向けに `DROP TRIGGER IF EXISTS trigger_lark_sync_visits ON visits;` と `DROP FUNCTION IF EXISTS notify_lark_sync();` を含む削除マイグレーションを作る。
- [x] `supabase/migrations/functions/lark-sync/` を削除またはarchiveへ移動する。
- [ ] `LARK_APP_ID`、`LARK_APP_SECRET`、`LARK_BASE_*`、`LARK_STATS_*`、`LARK_ALERTS_*` を必須/推奨環境変数から外す。
- [ ] Lark同期確認をE2E/本番テストチェックリストから外す。
- [ ] 削除後に親御さん問診、兄弟登録、スタッフ診断、レポート表示、LINE送信が動作することを確認する。

---

## 代替

- 当日監視: `/api/admin/realtime-status` と管理画面
- 後日集計: Postgres集計View、CSV/API出力
- レポート: `/report/{visitId}` と `reports.visit_id`
