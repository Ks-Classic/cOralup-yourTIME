## 概要

スタッフの識別・認証にLINE公式アカウント（Messaging API）+ LIFF（最小構成）を採用。
**LIFFは初回ログイン時のみ使用**し、以降は通常Webアプリをブラウザで利用。

### なぜこの構成か

| 案 | チャネル数 | 初回UX | 実装コスト | 審査 |
|----|-----------|--------|-----------|------|
| Messaging + LINEログイン | 2つ | OAuth認可画面あり | 中 | 不要 |
| **Messaging + LIFF（初回のみ）** | **2つ** | **自動（許可不要）** | **低** ✅採用 | **不要** |
| LINEミニアプリ | 1つ | 自動 | 低 | 必要（1-2週間） |

## 一人二役テスト方法（親 + スタッフ）

### 前提
- 親用とスタッフ用は**同じプロバイダー「cOralup」配下** → 同じ `lineUserId`
- 別のLINE公式アカウントを友だち追加するだけでOK

### テスト手順

```
1. 親用アカウント「cOralup」を友だち追加
   → profiles: role='parent' で登録される

2. スタッフ用アカウント「cOralupスタッフ」を友だち追加
   → 同じ lineUserId を検出
   → profiles: secondaryRole='staff' が追加される

3. スタッフ用LIFFでログイン
   → セッションCookie発行
   → /staff/home にアクセス可能

4. 親用LIFFでも引き続き利用可能
   → 問診フローなど影響なし
```

### 確認ポイント

```sql
-- 一人二役の確認
SELECT id, line_user_id, display_name, role, secondary_role, is_active
FROM profiles
WHERE line_user_id = 'U_your_line_user_id';
-- → role='parent', secondary_role='staff' であること
```
