# 03-06: スタッフLINE認証（LIFF最小構成）

**優先度**: 🔴 P0（YourTIMEイベント必須）  
**関連仕様書**: [28-スタッフLINE認証仕様書.md](../../designe/28-スタッフLINE認証仕様書.md)

---

## 概要

スタッフの識別・認証にLINE公式アカウント（Messaging API）+ LIFF（最小構成）を採用。
**LIFFは初回ログイン時のみ使用**し、以降は通常Webアプリをブラウザで利用。

### なぜこの構成か

| 案 | チャネル数 | 初回UX | 実装コスト |
|----|-----------|--------|-----------|
| Messaging + LINEログイン | 2つ | OAuth認可画面あり | 中 |
| **Messaging + LIFF（初回のみ）** | **1つ** | **自動（許可不要）** | **低** ✅採用 |

#### 5.1 詳細: スタッフ紐付けフロー

```mermaid
sequenceDiagram
    participant Staff as スタッフ (認証済み)
    participant QR as QRスキャン画面
    participant API as /api/staff/session
    participant DB as Supabase

    Staff->>QR: QRスキャン
    QR->>QR: visit_id取得
    QR->>API: POST /api/staff/session/assign
    Note over API: Cookie から staff_profile_id 取得
    API->>DB: UPDATE visits SET staff_profile_id = ?
    DB-->>API: OK
    API-->>QR: 200 OK
    QR->>Staff: 診断画面へ遷移
```

**API設計:**
```typescript
// POST /api/staff/session/assign
{
  visit_id: string  // QRから取得
}
// → Cookie の staff_session から staff_profile_id を取得
// → visits.staff_profile_id を更新
```

#### 5.3 詳細: 対応履歴API

```typescript
// GET /api/staff/history
// Cookie認証必須
// Response:
{
  data: [
    {
      id: string,           // visit_id
      visit_date: string,
      status: string,
      child: {
        first_name: string,
        last_name: string,
        birthday: string
      },
      session_id: string
    }
  ]
}
```
