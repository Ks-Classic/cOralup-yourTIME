-- 送信失敗のvisit_idを確認
SELECT 
  v.id,
  v.status,
  lm.status as line_status,
  lm.error_message
FROM visits v
LEFT JOIN line_message_logs lm ON v.id = lm.visit_id
WHERE v.status = 'diagnosis_completed'
  AND (lm.status = 'failed' OR lm.id IS NULL);

## 3. システム全体障害時の対応

### 3.1 障害レベル定義

| レベル | 状態 | 対応 |
|--------|------|------|
| Level 1 | 一部機能不調 | 代替手順で続行 |
| Level 2 | Vercel/API停止 | 紙面バックアップ運用 |
| Level 3 | Supabase停止 | 紙面運用+後日データ入力 |
| Level 4 | LINE障害 | Web直接アクセス案内 |

### 3.2 紙面バックアップフロー

**事前準備チェックリスト:**
- [ ] 紙の問診票（50部印刷）
- [ ] 紙の診断シート（50部印刷）
- [ ] 連絡先記入欄付きシート
- [ ] スタッフ用記入ガイド

**運用フロー:**

```
1. 親御さん
   紙の問診票を手渡し
   ↓
   問診票記入
   ↓
   受付番号札を渡す（連番）

2. スタッフ
   紙の診断シートに記入
   ↓
   写真は端末に保存
   ↓
   「後日LINE送信」と案内

3. イベント後
   紙データをシステムに入力
   ↓
   レポート生成→LINE送信
```

| 4 | AIレポート欠損 | 再分析実行 | □ |

### 4.2 データ整合性確認

```sql
-- 整合性チェッククエリ
SELECT 
  v.id as visit_id,
  v.status,
  CASE WHEN c.id IS NULL THEN '❌ child欠損' ELSE '✓' END as child_check,
  CASE WHEN qr.count = 0 THEN '❌ 問診欠損' ELSE '✓' END as questionnaire_check,
  CASE WHEN dr.count = 0 AND v.status IN ('diagnosis_completed', 'report_sent') 
       THEN '❌ 診断欠損' ELSE '✓' END as diagnosis_check
FROM visits v
LEFT JOIN children c ON v.child_id = c.id
LEFT JOIN (
  SELECT visit_id, COUNT(*) as count FROM questionnaire_responses GROUP BY visit_id
) qr ON v.id = qr.visit_id
LEFT JOIN (
  SELECT visit_id, COUNT(*) as count FROM diagnosis_responses GROUP BY visit_id
) dr ON v.id = dr.visit_id
WHERE v.created_at > NOW() - INTERVAL '1 day';
```
