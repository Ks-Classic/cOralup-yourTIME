# エラーハンドリング方針 (cOralup Platform)

## 1. 基本原則

1. **ユーザーフレンドリー**: 技術的エラーメッセージをそのまま表示しない
2. **リカバリー重視**: 可能な限り操作を継続できるようにする
3. **ログ記録**: 全エラーはサーバーサイドでログ記録（デバッグ用）
4. **オフライン対応**: ネットワーク断でもローカル保存で継続可能

---

## 2. エラー分類と対応方針

### 2.1 APIエラー（サーバーサイド）

| HTTPステータス | 意味 | ユーザー表示 | 対応 |
|---------------|------|------------|------|
| `400` | リクエスト不正 | 「入力内容を確認してください」 | バリデーションエラー表示 |
| `401` | 認証エラー | 「ログインしてください」 | ログイン画面へリダイレクト |
| `403` | 権限エラー | 「この操作は許可されていません」 | 前の画面へ戻る |
| `404` | リソースなし | 「データが見つかりません」 | 一覧画面へ戻る |
| `500` | サーバーエラー | 「一時的なエラーです。再試行してください」 | リトライボタン表示 |

### 2.2 ネットワークエラー（クライアントサイド）

| エラー種別 | ユーザー表示 | 対応 |
|-----------|------------|------|
| `TypeError: Failed to fetch` | 「インターネット接続を確認してください」 | オフラインバナー表示 |
| タイムアウト | 「通信に時間がかかっています」 | リトライボタン |
| DNS解決失敗 | 「サーバーに接続できません」 | サポート連絡先表示 |

### 2.3 バリデーションエラー（フォーム）

| エラー種別 | 表示位置 | 例 |
|-----------|---------|-----|
| 必須項目未入力 | フィールド直下 | 「お名前を入力してください」 |
| 形式不正 | フィールド直下 | 「正しい電話番号を入力してください」 |
| 範囲外 | フィールド直下 | 「1〜100の数値を入力してください」 |
| 複合エラー | フォーム上部 | 「入力内容に問題があります（3件）」 |

## 3. 機能別エラーハンドリング

### 3.1 LINE認証

```typescript
// エラーパターン
try {
  await lineLogin()
} catch (error) {
  if (error.code === 'invalid_request') {
    // LINE側の設定問題
    showError('LINE連携に問題が発生しました。スタッフにお声がけください')
  } else if (error.code === 'access_denied') {
    // ユーザーがキャンセル
    showInfo('LINEログインがキャンセルされました')
  } else {
    // その他
    showError('ログインに失敗しました。もう一度お試しください')
  }
}
```

### 3.2 QRコードスキャン

```typescript
// エラーパターン
const handleQRScan = async (data: string) => {
  try {
    const visitId = parseQRData(data)
    const visit = await fetchVisit(visitId)
    
    if (!visit) {
      showError('このQRコードは無効です。親御さんに再表示をお願いしてください')
      return
    }
    
    if (visit.status !== 'questionnaire_completed') {
      showError('問診がまだ完了していません')
      return
    }
    
    // 成功
    navigateToDiagnosis(visitId)
    
  } catch (error) {
    if (error.name === 'NotAllowedError') {
      showError('カメラの使用が許可されていません。設定を確認してください')
    } else {
      showError('QRコードの読み取りに失敗しました')
    }
  }
}
```

### 3.3 画像アップロード

```typescript
// エラーパターン
const uploadPhoto = async (file: File) => {
  // サイズチェック
  if (file.size > 10 * 1024 * 1024) {
    showError('画像サイズが大きすぎます（10MB以下）')
    return
  }
  
  // 形式チェック
  if (!['image/jpeg', 'image/png', 'image/webp'].includes(file.type)) {
    showError('JPEG、PNG、WebP形式の画像を選択してください')
    return
  }
  
  try {
    const url = await supabaseStorage.upload(file)
    return url
  } catch (error) {
    if (error.statusCode === 413) {
      showError('ファイルが大きすぎます')
    } else {
      showError('アップロードに失敗しました。再試行してください')
    }
  }
}
```

### 3.4 AI分析

```typescript
// エラーパターンとフォールバック
const analyzeWithAI = async (data: AnalysisInput) => {
  try {
    const result = await callGeminiAPI(data)
    return result
  } catch (error) {
    console.error('AI分析エラー:', error)
    
    // フォールバック: 手動入力モードへ
    showWarning(
      'AI分析に失敗しました。手動でコメントを入力してください',
      { 
        action: () => switchToManualMode(),
        actionLabel: '手動入力へ'
      }
    )
    return null
  }
}
```

### 3.5 LINE送信

```typescript
// リトライ付きエラーハンドリング
const sendLineMessage = async (userId: string, message: any, retries = 3) => {
  for (let i = 0; i < retries; i++) {
    try {
      await lineClient.pushMessage(userId, message)
      return { success: true }
    } catch (error) {
      if (i === retries - 1) {
        // 最終リトライも失敗
        console.error('LINE送信失敗:', error)
        return { 
          success: false, 
          fallback: 'screen' // 画面表示にフォールバック
        }
      }
      // リトライ前に待機
      await sleep(1000 * (i + 1))
    }
  }
}
```

## 4. UI表示パターン

### 4.1 トースト通知（軽微なエラー）

```tsx
// 使用例
toast.error('保存に失敗しました', {
  action: {
    label: '再試行',
    onClick: () => retry()
  }
})
```

### 4.2 インラインエラー（フォームバリデーション）

```tsx
<Input
  {...register('name')}
  error={errors.name?.message}
/>
// 表示: フィールド下に赤文字でエラーメッセージ
```

### 4.3 フルスクリーンエラー（致命的エラー）

```tsx
<ErrorScreen
  title="エラーが発生しました"
  message="サーバーとの通信に失敗しました"
  actions={[
    { label: '再試行', onClick: retry },
    { label: 'ホームへ戻る', onClick: goHome }
  ]}
/>
```

### 4.4 オフラインバナー

```tsx
// 画面上部に固定表示
<OfflineBanner>
  インターネット接続がありません。一部機能が制限されます。
</OfflineBanner>
```
