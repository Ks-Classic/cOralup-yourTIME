**※この「次へ」ボタン押下時に、以下が実行されます:**
- `profiles` テーブル更新（`first_name`, `last_name`, `phone_number`）

- **`visits` テーブル作成（`visit_id` UUID生成、`session_id` 生成、`status='questionnaire_in_progress'`）**

#### 問診票詳細入力画面（マルチステップ）
```mermaid
graph LR
    A[ステップ1: 既往歴] --> B[ステップ2: 現在の悩み]
    B --> C[ステップ3: 理想の状態]
    C --> D[ステップ4: 追加コメント]
```

**各ステップの詳細設計:**

**ステップ1: 既往歴**
- チェックボックス形式で複数選択可能
- 「特になし」オプションの設置
- スクロール可能な領域で情報の詰め込みすぎを防ぐ

**ステップ2: 現在の悩み**
- 口腔・姿勢関連の悩みをカテゴリ別に分類
- 各カテゴリで具体的な症状を選択
- 自由記述欄で詳細な説明を可能に

**ステップ3: 理想の状態**
- ポジティブな目標設定を促す項目
- 複数の理想像を選択可能
- モチベーション向上につながる表現

**ステップ4: 追加コメント**
- スタッフへの伝達事項を記入
- 任意項目だが、詳細な情報提供を促すUI

## スタッフユーザー 詳細フロー

### スタッフワークフロー概要
```mermaid
graph LR
    A[QR読み込み] --> B[問診確認]
    B --> C[写真撮影]
    C --> D[診断入力]
    D --> E[分析・レポート]
    E --> F[LINE送信]
    F --> G[診断完了]
```

### DB保存タイミング（サーバーAPI経由）

| ステップ | 操作 | API | DB操作 |
|----------|------|-----|--------|
| QR読み込み | スキャン成功 | `GET /api/staff/session` | visits.staff_profile_id UPDATE |
| 写真撮影 | 撮影完了 | `POST /api/upload` | Storage + visit_photos INSERT |
| 診断入力 | 項目変更 | `POST /api/diagnoses` | diagnosis_responses INSERT/UPDATE |
| AI分析 | 分析実行 | `POST /api/ai/analyze` | ai_analysis_results INSERT |
| コメント修正 | 保存 | `PUT /api/ai/analyze` | ai_analysis_results UPDATE |
| LINE送信 | 送信 | `POST /api/line/send-report` | line_message_logs INSERT + visits.status UPDATE |

**注意**: RLS ON環境のため、全DB操作はサーバーAPI経由（Service Role）で実行。クライアントから直接Supabaseを呼び出さない。

|----|-----|------|------|------|

### 4. 診断結果入力フロー

**診断開始で実際にお子さんの測定しながら、結果をスマホに入力**

#### 診断項目詳細設計
**姿勢評価セクション:**
- 頭部位置: 正常・前方突出・後方傾斜
- 肩バランス: 左右対称・左肩挙上・右肩挙上
- 背骨カーブ: 正常・過剰前弯・過剰後弯
- 骨盤傾き: 正常・前方傾斜・後方傾斜
- 足部バランス: 正常・内反・外反

**口腔機能評価セクション:**
- 咬合状態: 正常咬合・開咬・過蓋咬合・交叉咬合
- 歯並び: 正常・叢生・上顎前突・下顎前突・開咬
- 舌位置: 正常・低位舌・舌突出
- 清潔度: 良好・要改善・不良

#### 診断入力の特徴
- **リアルタイム入力**: 実際にお子さんを測定しながら、その場でスマホに入力
- **写真撮影**: カメラで撮影しながら診断項目を入力（横向き姿勢、正面姿勢、口腔内写真など）
- **チェックボックス入力**: 診断項目をチェックボックスで選択しながら測定
- **メモ・コメント機能**: 構造化されたメモテンプレート、音声入力機能、画像添付機能
