# AI分析設定・テストツール仕様書

**最終更新: 2024-12-19**

---

## 概要

診断結果からAIレポートを生成する機能の設定・テストツール。
DBの診断項目を元にした変数マッピング、プロンプトの調整、テストケースでの検証を行う。

---

## アクセス

```
/admin/ai-test
```

管理画面（/admin）のタブナビゲーションから「AI設定」でアクセス。

---

## 機能一覧

### 1. プロンプト編集
- カスタムプロンプトテンプレートの作成・編集
- 変数プレースホルダー（`{{変数名}}`）の挿入
- プロンプトのDB保存・読み込み

### 2. 変数マネージャー
- 動的変数の定義と管理
- DB診断項目からのマッピング
- プレースホルダーへの自動置換

### 3. テストケース生成
- 年齢プリセット（乳児/幼児/学童/思春期）
- 状態プリセット（良好/要観察/要指導/重度）
- ランダム/手動の値設定

### 4. レポート生成テスト
- テストケース値でAI生成を実行
- 変数置換のデバッグ表示
- 処理時間の計測

## 変数マネージャー仕様

### 変数の定義

```typescript
interface VariableConfig {
  variableName: string      // 変数名（例: "診断結果"）
  itemIds: string[]         // 選択された診断項目ID (UUID)
}
```

### 変数置換の流れ

1. **変数定義**: 管理者がUI上で変数名と対象項目を設定
2. **プロンプト記述**: `{{診断結果}}` のようにプレースホルダーを記述
3. **レポート生成時**:
   - `itemIds` に対応する値をマップから取得
   - 「質問名: 値」形式でフォーマット
   - プレースホルダーを置換

### プレースホルダー形式

```
{{変数名}}
```

例:
```
あなたは口腔育成の専門家として、診断結果{{診断結果}}から親御さん向けのレポートを生成してください。
```

置換後:
```
あなたは口腔育成の専門家として、診断結果
舌小帯短縮症: 無
ハート舌: あり
低位舌: 無
歯列・咬合: 正常
...
から親御さん向けのレポートを生成してください。
```

## データフロー

### テストモード

```
┌─────────────┐      ┌───────────────────┐      ┌─────────────┐
│ テストケース │ ──→ │ diagnosisMeta     │ ──→ │ API Route   │
│ 設定画面    │      │ questionnaireMeta │      │ 変数置換    │
└─────────────┘      └───────────────────┘      └─────────────┘
      │                      │                        │
      │  DB項目構造を使用    │  itemId: {q, v} 形式   │  マップ登録
      ↓                      ↓                        ↓
  diagnosisCategories   formatForAPI()          allItemsMap
  (DBから取得)          で変換                  に登録・検索
```

### 本番モード

```
┌─────────────┐      ┌───────────────────┐      ┌─────────────┐
│ visitId     │ ──→ │ diagnosis_responses│ ──→ │ API Route   │
│             │      │ (DBから取得)       │      │ 変数置換    │
└─────────────┘      └───────────────────┘      └─────────────┘
      │                      │                        │
      │  visits.session_id   │  diagnosis_items.id   │  マップ登録
      ↓                      ↓                        ↓
  questionnaires        rData                   allItemsMap
  visits から取得       としてJOIN取得          id/質問名で登録
```

## DBスキーマ

### ai_prompts テーブル

```sql
CREATE TABLE ai_prompts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  label VARCHAR(255) NOT NULL,           -- プロンプト名
  prompt_template TEXT NOT NULL,         -- プロンプト本文
  variable_config JSONB,                 -- 変数設定 JSON
  model_name VARCHAR(100),               -- 使用モデル名
  is_active BOOLEAN DEFAULT false,       -- 本番適用フラグ
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

### variable_config の構造

```json
[
  {
    "variableName": "診断結果",
    "itemIds": [
      "efb9621d-922a-4a0b-951a-d88ccda77bac",
      "aed1d3ec-3c16-42ad-af21-7640ddf2372d",
      ...
    ]
  }
]
```

## 本番適用の流れ

1. **テスト**: AI設定ページでプロンプトと変数を調整
2. **保存**: 満足のいく設定をDBに保存
3. **有効化**: `is_active: true` で本番適用
4. **本番実行**: スタッフ診断画面からレポート生成時に適用

### 本番レポート生成時の動作

1. `visitId` からセッションを特定
2. `diagnosis_responses` から診断結果を取得
3. `ai_prompts` から有効なプロンプトを取得
4. `variable_config` に基づいて変数を置換
5. Gemini APIでレポート生成
6. 結果をレポートとして保存
