# 問診票・診断評価項目の管理設計 - 最適化アプローチ

## 概要

問診票項目やスタッフ評価チェック項目の管理方法について、開発効率・運用効率・データ保存の観点から最適な設計を提案します。

## 現状分析

### 現在の実装状況

1. **ハードコーディング方式**
   - `src/data/preschooler-form-schema.ts` - 未就学児用問診票
   - `src/data/elementary-form-schema.ts` - 小学生以上用問診票
   - `src/data/staff-diagnosis-items.ts` - スタッフ診断評価項目

2. **動的フォームシステム（設計済み・一部実装）**
   - `form_schemas` テーブル（DB）
   - `form_responses` テーブル（DB）
   - 管理画面（`src/app/(admin)/forms/page.tsx`）

## 設計アプローチの比較

### アプローチ1: 完全ハードコーディング

#### メリット
- ✅ **型安全性**: TypeScriptの型チェックが完全に機能
- ✅ **パフォーマンス**: ビルド時に最適化、ランタイムオーバーヘッドなし
- ✅ **開発速度**: 初期実装が速い
- ✅ **バージョン管理**: Gitで完全に管理可能
- ✅ **デプロイの確実性**: コードレビューで変更を確認可能

#### デメリット
- ❌ **変更の煩雑さ**: 項目変更時にコード修正→デプロイが必要
- ❌ **運用コスト**: 開発者が必要、緊急変更が困難
- ❌ **イベント別カスタマイズ**: 各イベントで異なる項目に対応困難

### アプローチ2: 完全動的管理（DB管理）

#### メリット
- ✅ **柔軟性**: 管理者がUIから項目を追加・変更可能
- ✅ **運用効率**: 開発者不要で変更可能
- ✅ **イベント別対応**: 各イベントで異なるフォームを簡単に作成
- ✅ **リアルタイム反映**: 変更が即座に反映

#### デメリット
- ❌ **型安全性の低下**: ランタイムでの型チェックが必要
- ❌ **パフォーマンス**: DBアクセスが必要、キャッシュ管理が必須
- ❌ **バリデーション**: スキーマ変更時の既存データ整合性問題
- ❌ **バージョン管理**: DBの変更履歴管理が複雑
- ❌ **デプロイリスク**: 本番環境での誤操作リスク

### アプローチ3: ハイブリッド（推奨）⭐

**基本スキーマはハードコーディング、カスタマイズは動的管理**

#### 設計思想

## 実装アーキテクチャ

### スキーマ解決フロー

```typescript
// スキーマ解決ロジック
async function resolveFormSchema(
  eventId: string,
  formType: 'preschooler' | 'elementary' | 'diagnosis'
) {
  // 1. イベント別カスタムスキーマを検索
  const customSchema = await db.formSchemas.findByEventId(eventId, formType)
  
  if (customSchema) {
    // 2. 基本スキーマを読み込み
    const baseSchema = getBaseSchema(formType)
    
    // 3. マージ処理
    return mergeSchemas(baseSchema, customSchema)
  }
  
  // 4. カスタムスキーマがない場合は基本スキーマを返す
  return getBaseSchema(formType)
}
```

## パフォーマンス最適化

### 1. キャッシュ戦略

```typescript
// 基本スキーマ: ビルド時にバンドル（キャッシュ不要）
// カスタムスキーマ: Redis/メモリキャッシュ
const schemaCache = new Map<string, FormSchemaConfig>()

async function getCachedSchema(schemaId: string) {
  if (schemaCache.has(schemaId)) {
    return schemaCache.get(schemaId)
  }
  
  const schema = await db.formSchemas.findById(schemaId)
  schemaCache.set(schemaId, schema)
  return schema
}
```
