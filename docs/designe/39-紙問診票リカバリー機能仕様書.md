**作成日**: 2026年1月1日
**最終更新**: 2026年1月1日
**ステータス**: 実装完了（テスト待ち）

## 1. 背景と目的

### 1.1 背景
2025年12月開催のYourTIMEイベントにおいて、LINE通信の上限に達したことにより、一部の来場者（約25件）がアプリでの問診入力ができず、**紙のカウンセリングシート**で対応した。

この紙データをDBに取り込み、AI分析・レポート生成を行い、親御さんへレポートURLを提供する必要がある。

### 1.2 目的
1. **スプレッドシートから基本情報（名前・生年月日・メアド）を先行インポート**する
2. 紙問診票の画像から、問診データをDBに登録する
3. 既存の診断入力UI・AI分析・レポート生成機能を活用し、一貫したフローでリカバリーする
4. 最終的にレポートURLを発行し、親御さんへメールで手動送信する

### 1.3 対象件数
- **約25件**（紙で対応した来場者）

### 1.4 利用可能なデータソース

#### スプレッドシート（Googleフォーム回答）
イベント当日、来場者がGoogleフォームで入力した基本情報。

| 列名 | 内容 | 用途 |
|:---|:---|:---|
| タイムスタンプ | 登録日時 | 参考情報 |
| お名前(お子様) | 漢字 | DB検索キー、children登録 |
| ふりがな | ひらがな | children登録 |
| お子様の生年月日 | YYYYMMDD形式 | DB検索キー、children登録 |
| メールアドレス | 親のメアド | profiles登録、レポート送信先 |

#### 紙問診票
アプリが使えなかった来場者が記入した紙のカウンセリングシート。
- 基本情報（名前、生年月日、都道府県、性別）
- 問診回答（睡眠、習い事、食事など）

### 1.5 処理方針
1. **スプレッドシートを先行インポート**（Phase 1）
   - 名前 + 生年月日 で既存DBを検索
   - **該当者がいれば既存のchildレコードを使用**
   - **該当者がいなければ新規作成**（profiles + children + visits）
2. **紙画像から問診データを追加登録**（Phase 2）
   - インポート済みのchildに紐づくvisitに問診データを登録

| ID | 要件 |

| 項目 | 理由 |

| バッチ処理 | 1件ずつ確認しながら処理する |

```
              ↓

              ↓

         - 問診回答（チェック項目）を抽出
              ↓
[Step 4] 抽出結果を画面に表示・確認・修正
              ↓
[Step 5] 「問診データを登録」ボタン
         → questionnaire_responses に登録

              ↓

         → 管理者が手動でメール送信
```

### 3.2 処理フロー詳細

#### Step 1-2: 画像アップロード → Gemini解析
1. 管理者が紙画像（JPG/PNG）をドラッグ&ドロップ
2. Gemini Flash 2.0 で画像を解析
3. JSON形式で問診データを抽出

#### Step 3: 抽出結果の確認
1. 抽出された名前・生年月日・問診項目を表示
2. 管理者が目視で確認・修正可能

#### Step 4: DB検索
1. 名前（漢字）+ 生年月日でchildrenテーブルを検索
2. 該当者がいれば、そのchildに紐づくvisitを表示
3. 該当者がいなければ、新規登録フォームを表示

#### Step 5: 問診データ登録
1. 該当visitの`questionnaire_responses`に問診データを登録
2. visitがなければ新規作成

#### Step 6-9: 診断〜レポート
1. 既存の診断入力画面（`/staff/diagnosis/[visitId]`）へ遷移
2. 管理者が診断項目を手動入力
3. AI分析・レポート生成（既存機能を使用）
4. レポートURL（`/report/[visitId]`）を表示

### 5.2 Phase 1 API詳細（スプレッドシートインポート）

#### 5.2.0a POST `/api/admin/spreadsheet-import/parse`

CSVファイルをパースし、プレビュー用データを返す。

**リクエスト**
```typescript
// Content-Type: multipart/form-data
{
  file: File  // CSVファイル
}
```

**レスポンス**
```typescript
{
  success: boolean
  data: {
    rows: Array<{
      rowNumber: number
      timestamp: string        // "2025/12/21 13:56:14"
      childName: string        // "稲田 悠真"
      furigana: string         // "いなだ ゆうま"
      birthday: string         // "20190929" → "2019-09-29"に変換
      email: string            // "cece19850724@gmail.com"
    }>
    totalCount: number
  }
}
```

各行について既存DBを検索し、マッチ状況を返す。

**リクエスト**
```typescript
{
  rows: Array<{
    childName: string
    birthday: string  // "2019-09-29"
  }>
}
```

**レスポンス**
```typescript
{
  success: boolean
  data: {
    results: Array<{
      rowNumber: number
      status: "found" | "not_found"
      existingChild?: {
        id: string
        firstName: string
        lastName: string
        parentProfileId: string
      }
      existingVisit?: {
        id: string
        status: string
      }

      found: number

  }
```

## 6. DB連携

### 6.1 使用テーブル

| テーブル | 用途 | 操作 |
|:---|:---|:---|
| `profiles` | 親プロフィール | SELECT / INSERT / UPDATE |
| `children` | 子供情報 | SELECT / INSERT |
| `visits` | 来場セッション | SELECT / INSERT |
| `questionnaire_responses` | 問診回答 | INSERT |
| `questionnaire_items` | 問診項目マスタ | SELECT |

### 6.2 インポート時のケース分岐

スプレッドシートの各行について、以下のケースで処理を分岐する。

#### ケースB: 既存childあり + profileにメアドなし
1. 名前 + 生年月日 で `children` テーブルを検索
2. 該当childの `parent_profile_id` を取得
3. 該当profileの `email` を**UPDATE**（スプレッドシートのメアドで更新）
4. 既存childに紐づく新規visitを作成

```sql
-- profilesにメアドを追加
UPDATE profiles SET email = 'xxx@gmail.com' WHERE id = [parent_profile_id];

-- 新規visitを作成
INSERT INTO visits (session_id, child_id, parent_profile_id, ...) VALUES (...);
```

#### ケースC: 既存childなし（完全新規）
1. **profilesを新規作成**（メアドのみ、親の名前は空欄）
2. **childrenを新規作成**（スプレッドシートの子供情報）
3. **visitsを新規作成**

> **注意**: 親御さんの名前はスプレッドシートにないため、profilesには**メアドだけ**を登録する。

```sql
-- 親profile（メアドのみ）を作成
INSERT INTO profiles (
  email,           -- 'cece19850724@gmail.com'（スプレッドシートから）
  role,            -- 'parent'
  first_name,      -- NULL（不明）
  last_name,       -- NULL（不明）
  line_user_id,    -- NULL（アプリ未使用のため）
  created_at
) VALUES (...);

-- 子供情報を作成
INSERT INTO children (
  parent_profile_id,  -- 上で作成したprofileId
  first_name,         -- '悠真'（スプレッドシートから分割）
  last_name,          -- '稲田'（スプレッドシートから分割）
  first_name_kana,    -- 'ゆうま'（スプレッドシートから分割）
  last_name_kana,     -- 'いなだ'（スプレッドシートから分割）
  birthday,           -- '2019-09-29'（スプレッドシートから変換）
  created_at
) VALUES (...);

-- visitを作成
INSERT INTO visits (
  session_id,         -- 自動生成（例: 'PAPER-20260101-001'）
  child_id,           -- 上で作成したchildId
  parent_profile_id,  -- 上で作成したprofileId
  status,             -- 'waiting'
  current_step,       -- 'waiting'
  visit_date,         -- '2025-12-21'（イベント日）
  created_at
) VALUES (...);
```

### 6.3 データフロー図

```
[スプレッドシートCSV]
       ↓
[各行をループ処理]
       ↓
[children検索] 名前 + 生年月日
       ↓
  ┌────┴────┐
  ↓         ↓
[既存あり] [既存なし]
  ↓         ↓
[ケースB]  [ケースC]
  ↓         ↓
profilesに  profiles INSERT（メアドのみ）
メアドUPDATE     ↓
  ↓         children INSERT
  ↓              ↓
  └────┬────────┘
       ↓
[visits INSERT] → visitId, sessionId生成
       ↓
[Phase 2へ: 問診データ登録]
```

### 6.4 名前の分割ロジック

スプレッドシートの「お名前(お子様)」は「姓 名」形式（スペース区切り）なので、分割して登録する。

```typescript
// 例: "稲田 悠真" → ["稲田", "悠真"]
const [lastName, firstName] = childName.split(/\s+/);

// 例: "いなだ ゆうま" → ["いなだ", "ゆうま"]
```
