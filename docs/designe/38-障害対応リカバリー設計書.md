# 障害対応リカバリー設計書

**作成日**: 2025-12-19
**対象イベント**: YourTIME 2024/12/21

---

## 1. 概要

本書は、Coralupアプリが障害により使用できなくなった場合のリカバリー方法を定義する。
ハイブリッド対応（Googleフォーム + 紙バックアップ）を採用し、複数レベルの障害に段階的に対応する。

---

## 2. 障害レベル定義

| レベル | 障害内容 | 影響範囲 | 対応方法 |
|--------|---------|---------|---------|
| **L1** | 親御さんのスマホ/LINE問題 | 個別の親御さんのみ | Googleフォーム(問診) + 手書き受付番号 |
| **L2** | スタッフ端末の軽微な問題 | 個別スタッフのみ | 別端末で代替 or Googleフォーム(診断) |
| **L3** | インターネット接続断(一時的) | 会場全体 | 紙で記録 → 復旧後入力 |
| **L4** | 全システムダウン | 全機能 | 完全紙運用モード |

---

## 3. 障害対応フローチャート

```
[障害発生]
    │
    ├─ Q1: アプリは開けるか？
    │   ├─ Yes → Q2へ
    │   └─ No → Q3へ
    │
    ├─ Q2: 特定の親御さん/スタッフのみ？
    │   ├─ Yes (個別問題) → レベル1/2対応
    │   │   ├─ 親御さん問題 → Googleフォーム(問診)を案内
    │   │   └─ スタッフ問題 → 別端末 or Googleフォーム(診断)
    │   └─ No (全体問題) → Q3へ
    │
    └─ Q3: インターネットは使えるか？
        ├─ Yes → レベル2対応 (Googleフォーム全面利用)
        └─ No → レベル3/4対応 (紙運用)
```

## 5. 運用フロー

### 5.1 レベル1対応（個別親御さん問題）

```
1. スタッフがGoogleフォーム(問診)のQRを親御さんに見せる
2. 親御さんがスマホでQR読み取り → Googleフォームで問診入力
3. スタッフが受付番号（例: A-001）を付与し、親御さんに伝える
4. スタッフは通常アプリで診断（受付番号をメモ欄に記載）
5. LINE送信時は「近日中にお送りします」と伝える
6. イベント後、Googleスプレッドシートからデータインポート
7. LINE/メールでレポート送信
```

### 5.2 レベル2対応（スタッフ端末問題）

```
1. 親御さんは通常アプリで問診 → QRコード表示
2. スタッフは別端末で対応 or Googleフォーム(診断)を使用
3. Googleフォーム使用時は受付番号で紐付け
4. 写真はGoogleフォームにアップロード or スマホで撮影後Drive保存
5. イベント後、Googleスプレッドシートからデータインポート
```

### 5.3 レベル3/4対応（全体障害）

```
1. 紙の問診票を親御さんに配布
2. 親御さんが紙に記入（ペン用意必須）
3. スタッフは紙の診断シートに記入
4. 写真はスマホで撮影（受付番号を写真に写す）
5. 紙は全て回収し、写真撮影して電子化
6. イベント後、手動またはOCRでデータ入力
```

## 6. データインポート手順

### 6.1 Googleスプレッドシートからのインポート

```bash
# 1. スプレッドシートをCSVエクスポート
# 2. インポートスクリプト実行
node scripts/import-backup-data.js --source=questionnaire.csv --type=questionnaire
node scripts/import-backup-data.js --source=diagnosis.csv --type=diagnosis
```

### 6.2 紙データからのインポート

1. 紙を写真撮影
2. Google Drive に日付フォルダを作成して保存
3. 手動でSupabase管理画面から入力 or CSVで一括インポート
