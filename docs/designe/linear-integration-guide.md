# Linear連携ガイド

## 📋 Linearでのプロジェクト管理方法

### 1. プロジェクト構造

#### 基本設定
- **プロジェクト名**: Coralup口腔育成プラットフォーム
- **チーム**: 開発チームメンバー全員を招待
- **サイクル**: 2週間スプリント
- **ステータス**: アクティブ

#### カテゴリ別エピック設定

**1. Frontend Development**
- 担当: フロントエンドチーム
- ラベル: `frontend`, `ui-ux`
- 優先度: 高

**2. Backend API Development**
- 担当: バックエンドチーム
- ラベル: `backend`, `api`
- 優先度: 高

**3. Database Setup**
- 担当: データベースチーム
- ラベル: `database`, `infrastructure`
- 優先度: 中

**4. AI Integration**
- 担当: AI/MLチーム
- ラベル: `ai`, `machine-learning`
- 優先度: 中

**5. Admin Panel Development**
- 担当: 管理者画面チーム
- ラベル: `admin`, `dashboard`
- 優先度: 高

**6. External Integrations**
- 担当: 外部連携チーム
- ラベル: `integration`, `external`
- 優先度: 中

**7. Testing & Deployment**
- 担当: DevOpsチーム
- ラベル: `testing`, `deployment`
- 優先度: 中

**8. Documentation**
- 担当: 技術文書チーム
- ラベル: `documentation`, `docs`
- 優先度: 低

### 2. タスク管理のベストプラクティス

#### タスクの粒度
- **ストーリー**: 各機能単位（例: 「動的フォームAPI実装」）
- **タスク**: 詳細作業（例: 「フォームスキーマ保存API作成」）
- **サブタスク**: 細かい作業（例: 「バリデーション実装」）

#### 命名規則
```
[接頭辞] 機能名 - 詳細説明

例:
- [API] 動的フォームAPI - スキーマ保存機能実装
- [UI] 親御さんレイアウト - 問診票フォーム実装
- [DB] インデックス最適化 - 回答データ検索高速化
```

#### 優先度設定
- **高**: 今週中に完了すべきタスク
- **中**: 今月中に完了すべきタスク
- **低**: 来月以降で対応可能なタスク

#### 担当者アサイン
- 各タスクに適切な担当者を設定
- チームメンバーのスキルセットを考慮
- 複数人で対応する場合は協働者も設定

### 3. 進捗追跡方法

#### ステータス管理
- **Todo**: 未着手
- **In Progress**: 作業中
- **In Review**: レビュー中
- **Done**: 完了

#### 進捗更新タイミング
- **作業開始時**: Todo → In Progress
- **作業完了時**: In Progress → Done
- **レビュー依頼時**: Done → In Review
- **レビュー完了時**: In Review → Done

#### 週次報告
- 毎週金曜日に進捗レポート更新
- 完了タスクのサマリー
- 問題点と解決策の共有
- 次週の目標設定

### 4. Linear活用Tips

#### キーボードショートカット
- `Ctrl/Cmd + K`: クイック検索
- `Ctrl/Cmd + N`: 新規作成
- `Tab + Q`: 自分のタスクのみ表示
- `Tab + A`: 自分にアサイン済みタスク

#### フィルター活用
- **担当者別**: 各メンバーの作業負荷確認
- **優先度別**: 緊急タスクの抽出
- **ラベル別**: カテゴリ別タスク管理
- **期限別**: 締切が近いタスクの確認

#### カスタムビュー
- **マイタスク**: 自分担当のタスク
- **チーム進捗**: 全員の作業状況
- **緊急タスク**: 高優先度のタスク
- **レビュー待ち**: レビューが必要なタスク

### 5. コミュニケーション

#### コメントの活用
- タスクの詳細説明
- 技術的な議論
- 問題点の共有
- 解決策の提案

#### 添付ファイル
- 設計書
- ワイヤーフレーム
- スクリーンショット
- 参考資料

#### メンション機能
- 担当者への通知: `@担当者名`
- チーム全体への通知: `@team`
- 特定のユーザーの注目喚起: `@ユーザー名`

### 6. スプリント計画

#### 2週間スプリントの流れ
1. **計画**: スプリント初日に目標設定
2. **実行**: タスク実行と日次更新
3. **レビュー**: 中間レビュー（スプリント中間）
4. **振り返り**: スプリント終了時の振り返り
5. **改善**: 次スプリントへの改善策実施

#### ベロシティ追跡
- 各スプリントの完了ストーリーポイント記録
- チームの開発速度の可視化
- 現実的な計画立案のためのデータ活用

### 7. 統合機能

#### GitHub連携
- プルリクエストとLinearタスクの自動連携
- コミットメッセージにタスクIDを含む
- ブランチ名にタスクIDを含む

#### Slack連携
- タスク更新時の通知
- 担当者へのメンション
- 進捗状況の共有

#### 外部ツール連携
- Figma: デザインの自動同期
- Notion: ドキュメント連携
- Google Drive: ファイル共有

### 8. トラブルシューティング

#### 一般的な問題と解決策

**問題**: タスクの見積もりが甘い
**解決**: タスクをより小さな単位に分解し、詳細な見積もりを実施

**問題**: 進捗が停滞している
**解決**: 担当者と1on1ミーティングを実施し、課題を特定・解決

**問題**: 優先度の判断が難しい
**解決**: チームミーティングで優先順位付けを議論し、合意形成

**問題**: ドキュメントが不足している
**解決**: 作業開始時に必要なドキュメントを確認し、不足分を追加

### 9. 成功指標

#### 測定指標
- **完了率**: 計画に対する実績の割合
- **ベロシティ**: スプリントあたりの完了タスク数
- **品質**: バグ発生率・レビュー通過率
- **予測精度**: 見積もり精度

#### 改善のためのKPI
- スプリント完了率: 90%以上を目指す
- バグ発生率: 5%以下に抑える
- レビュー turnaround time: 24時間以内
- タスク見積もり精度: 80%以上の精度
