## リスク管理 (Risk Management)

| リスク | 対策 | 担当 |
| :--- | :--- | :--- |
| **LINE Login審査遅延** | テストユーザー枠で開発、またはWeb Loginで代替。 | 開発 |
| **AI精度が出ない** | プロンプト調整を最優先。最悪、テンプレート文言を用意。 | 開発/社長 |
| **会場電波悪い** | 画像軽量化、localStorage活用。ポケットWi-Fi準備。 | 運営 |
| **QR読めない** | URL直打ちまたはリスト選択機能を予備で用意。 | 開発 |
| **DB移行トラブル** | 旧テーブル（questionnaires, diagnoses）は互換用に残置。 | 開発 |

## Lark連携詳細

### リアルタイム同期アーキテクチャ

```
スタッフ診断画面 → Supabase → Database Webhook → Edge Function → Lark Base
                    │                                    │
                    └── 1〜3秒 ──────────────────────────┘
```

### 同期対象データ

| Supabaseテーブル | Lark Baseテーブル | 同期タイミング |
|-----------------|------------------|---------------|
| diagnosis_responses | 診断結果 | INSERT時 |
| questionnaire_responses | 問診結果 | INSERT時 |
| sessions (status変更) | 来場者ログ | UPDATE時 |
| visits | 来場者ログ | INSERT時 |

### データ変換

**Supabase（縦持ち・正規化）:**
- 項目追加が容易
- データ整合性が保たれる
- 履歴管理がしやすい

**Lark Base（横持ち・集計用）:**
- 集計・フィルタが直感的
- ダッシュボード表示に最適
- 非エンジニアでも理解しやすい

## AI分析フロー

### データ取得 → AI分析 → レポート生成

```
1. Supabaseからデータ取得
   - sessions: 基本情報
   - questionnaire_responses: 問診回答
   - diagnosis_responses: 診断回答

2. プロンプト生成
   「5歳男児、以下の診断結果をもとに
    親御さん向けのアドバイスを生成してください:
    - 舌小帯短縮症: 有
    - 低位舌: 有
    - 口呼吸: 有
    - 問診: いびきあり、口ぽかんあり」

3. Gemini API呼び出し

4. レポート生成・PDF出力
```

### Lark連携との独立性

AI分析はSupabaseのデータを直接使用するため、Lark連携とは完全に独立。
Lark側の障害がAI分析に影響しない。
