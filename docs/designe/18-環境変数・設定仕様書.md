# 環境変数・設定仕様書 (cOralup Platform)

## 1. 環境変数一覧

### 1.1 Supabase関連（必須）

| 変数名 | 説明 | 例 | 取得場所 |
|--------|------|-----|----------|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase プロジェクトURL | `https://xxx.supabase.co` | Supabase Dashboard > Settings > API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 匿名キー（公開可） | `eyJhbGciOiJI...` | 同上 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase サービスロールキー（秘密） | `eyJhbGciOiJI...` | 同上 |

### 1.2 LINE関連（必須）

| 変数名 | 説明 | 例 | 取得場所 |
|--------|------|-----|----------|
| `LINE_CHANNEL_ID` | LINE Login チャネルID | `1234567890` | LINE Developers > Channel |
| `LINE_CHANNEL_SECRET` | LINE Login チャネルシークレット | `abcdef123456...` | 同上 |
| `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` | Messaging API アクセストークン | `xxxxxxxx...` | LINE Developers > Messaging API |

### 1.3 AI関連（必須）

| 変数名 | 説明 | 例 | 取得場所 |
|--------|------|-----|----------|
| `GOOGLE_AI_API_KEY` | Google AI Studio APIキー | `AIzaSy...` | Google AI Studio |
| `GOOGLE_GEMINI_MODEL` | 使用モデル名 | `gemini-2.5-pro` | - |

### 1.4 アプリケーション設定（必須）

| 変数名 | 説明 | 例 | 備考 |
|--------|------|-----|------|
| `NEXT_PUBLIC_APP_URL` | アプリの公開URL | `https://coralup.vercel.app` | Vercelデプロイ後に設定 |
| `STAFF_PIN_CODE` | スタッフ認証用PIN | `1234` | 4桁数字（MVP用） |

### 1.5 Lark連携（オプション）

| 変数名 | 説明 | 例 | 取得場所 |
|--------|------|-----|----------|
| `LARK_APP_ID` | Lark アプリID | `cli_xxx` | Lark Developer Console |
| `LARK_APP_SECRET` | Lark アプリシークレット | `xxx` | 同上 |
| `LARK_BASE_APP_TOKEN` | Lark Base アプリトークン | `bascnXXX` | Lark Base URL から取得 |
| `LARK_BASE_TABLE_ID` | 同期先テーブルID | `tblXXX` | 同上 |

## 2. .env.example テンプレート

```bash
# ===========================================
# cOralup 環境変数設定
# ===========================================
# このファイルを .env.local にコピーして値を設定してください
# cp .env.example .env.local

# -------------------------------------------
# Supabase (必須)
# -------------------------------------------
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# -------------------------------------------
# LINE (必須)
# -------------------------------------------
LINE_CHANNEL_ID=your-channel-id
LINE_CHANNEL_SECRET=your-channel-secret
LINE_MESSAGING_CHANNEL_ACCESS_TOKEN=your-access-token

# -------------------------------------------
# Google AI (必須)
# -------------------------------------------
GOOGLE_AI_API_KEY=your-google-ai-api-key
GOOGLE_GEMINI_MODEL=gemini-2.5-pro

# -------------------------------------------
# Application (必須)
# -------------------------------------------
NEXT_PUBLIC_APP_URL=http://localhost:3000
STAFF_PIN_CODE=1234

# -------------------------------------------
# Lark (オプション - BI連携用)
# -------------------------------------------
# LARK_APP_ID=cli_xxx
# LARK_APP_SECRET=xxx
# LARK_BASE_APP_TOKEN=bascnXXX
# LARK_BASE_TABLE_ID=tblXXX
```

## 3. 環境別設定

### 3.1 ローカル開発 (`.env.local`)
- Supabase: ローカルコンテナ (`localhost:54321`) または本番を直接使用
- LINE: テスト用チャネル推奨
- APP_URL: `http://localhost:3000`

### 3.2 Vercel Preview (`.env` in Vercel)
- Supabase: 本番プロジェクト
- LINE: 本番チャネル（Webhook URLはVercel Preview URLに設定）
- APP_URL: Vercel自動生成URL

### 3.3 Vercel Production
- 全て本番設定
- APP_URL: カスタムドメインまたはVercel本番URL

## 4. セキュリティ注意事項

### 公開可能（`NEXT_PUBLIC_` prefix）
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `NEXT_PUBLIC_APP_URL`

### 秘密（サーバーサイドのみ）
- `SUPABASE_SERVICE_ROLE_KEY` - RLSをバイパスできる強力なキー
- `LINE_CHANNEL_SECRET` - Webhook署名検証用
- `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` - メッセージ送信用
- `GOOGLE_AI_API_KEY` - AI API呼び出し用
- `STAFF_PIN_CODE` - スタッフ認証用
- `LARK_APP_SECRET` - Lark API認証用

## 5. 取得手順ガイド

### Supabase
1. https://supabase.com でプロジェクト作成
2. Settings > API から URL と Keys を取得

### LINE
1. https://developers.line.biz でプロバイダー作成
2. LINE Login チャネルを作成 → Channel ID, Secret 取得
3. Messaging API チャネルを作成 → Access Token 発行

### Google AI
1. https://aistudio.google.com でAPIキー作成
2. Gemini Pro モデルを有効化

### Lark
1. https://open.larksuite.com でアプリ作成
2. Base APIの権限を付与
3. App ID, Secret を取得

## 6. アカウント移行計画

### 開発フェーズ（現在）
**個人アカウントで各サービスを作成して開発を進める**

| サービス | アカウント | 用途 |
|---------|-----------|------|
| Supabase | 個人アカウント | 開発・テスト用プロジェクト |
| LINE | 個人アカウント | 開発用チャネル（テスト用） |
| Google AI | 個人アカウント | 開発用APIキー |
| Vercel | 個人アカウント | 開発用デプロイ |
| GitHub | 個人アカウント | コード管理 |

### 本番移行（12/15頃）
**cOralupドメインアカウント取得後、本番環境に移行**

#### 移行可能なサービス
- **Supabase**: Organizationに移行（Export → Import）
- **Google AI**: APIキー再発行
- **Vercel**: Team移行
- **GitHub**: Organization移行

#### LINE（本番用は新規作成が必要）
- **移行不可**: プロバイダー・チャネルは個人アカウントから移行できない
- **対応**: cOralupアカウントで本番チャネルを新規作成
- **開発用チャネル**: テスト用として残しておく

#### 移行時の注意事項
1. **環境変数の分離**: 開発用（`.env.local`）と本番用（Vercel環境変数）を分けて管理
2. **Webhook URL**: 開発用と本番用で異なるURLが必要（両方のチャネルに設定）
3. **データ移行**: SupabaseはExport/Importでデータを移行可能
4. **LINE友だち数**: 本番チャネルは新規作成のため、友だち数は0から開始
