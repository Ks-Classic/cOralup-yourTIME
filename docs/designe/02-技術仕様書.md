## 2. 開発環境アーキテクチャ (Docker & Supabase)

ローカル開発環境では、Dockerコンテナ技術を利用して本番同等のSupabase環境を再現する。
開発者は `Dockerfile` を記述する必要はなく、Supabase CLI が自動的に必要なコンテナ群をオーケストレーションする。

### ローカル構成図

```mermaid
graph TD
    subgraph "Host Machine (WSL2 / Mac)"
        DevServer[Next.js Dev Server<br/>(localhost:3000)]
        SupabaseCLI[Supabase CLI<br/>(Control Plane)]
        
        subgraph "Docker Containers (Managed by Supabase CLI)"
            ContainerDB[supabase_db<br/>(PostgreSQL 15)]
            ContainerAuth[supabase_auth<br/>(GoTrue)]
            ContainerRest[supabase_rest<br/>(PostgREST)]
            ContainerStorage[supabase_storage<br/>(Storage API)]
            ContainerStudio[supabase_studio<br/>(Dashboard GUI)]
        end
    end

    DevServer -->|Connect via Env Vars| ContainerDB
    DevServer -->|Connect via Env Vars| ContainerAuth
    SupabaseCLI -->|Manage| Docker Containers
```

### Dockerコンテナの役割
*   **supabase_db**: 本番と同じPostgreSQLデータベース。マイグレーションファイルによりスキーマ管理される。
*   **supabase_auth**: 認証サーバー。LINEログインなどのモックやトークン発行を行う。
*   **supabase_studio**: ローカル版の管理ダッシュボード（`localhost:54323`）。ブラウザからテーブル操作やログ確認が可能。
*   **supabase_storage**: 画像アップロードのテスト用ストレージ。

### 必要なセットアップ
1.  **Docker Desktop**: コンテナ実行ランタイムとして必須。
2.  **Supabase CLI**: コンテナの起動・停止、DBマイグレーション、型定義生成を行うツール。

## 3. 技術スタック詳細

### Frontend / BFF
*   **Framework**: Next.js 14 (App Router)
*   **Language**: TypeScript
*   **Styling**: Tailwind CSS, shadcn/ui
*   **State Management**: Zustand (Client State), React Query (Server State)
*   **Validation**: Zod + React Hook Form

### Backend / Database
*   **Platform**: Supabase (Managed PostgreSQL)
*   **Database**: PostgreSQL 15
*   **ORM/Query**: Supabase JS Client (PostgREST)
*   **Schema Management**: SQL Migrations (Supabase CLI)

### AI / External
*   **AI Model**: Google Gemini Pro (via Vertex AI or AI Studio)
*   **Messaging**: LINE Messaging API
*   **BI/Admin**: Lark Base (Synced via API)

## 4. プロジェクトディレクトリ構造 (Best Practices)

ツール標準への準拠と、アプリケーションロジックの明確な分離（Separation of Concerns）を両立する構成を採用する。

```
.
├── supabase/                 # [Tool Standard] Supabase設定・マイグレーション
│   ├── migrations/
│   └── config.toml
├── src/
│   ├── app/                  # [Next.js Standard] UIとAPI
│   │   ├── (auth)/           # 共通認証UI
│   │   ├── (exhibition)/     # [Logical Separation] 展示会用UI (URL: /parent, /staff)
│   │   ├── (platform)/       # [Logical Separation] 将来のSaaS用 (URL: /admin/...)
│   │   └── api/              # API Routes (BFF)
│   ├── agents/               # [Logical Separation] AIロジック (Prompt + Zod Schema)
│   │   ├── index.ts          # Agent Runner
│   │   └── <agent-name>/     # 個別AIエージェント定義
│   ├── lib/                  # [Convention] 共通ライブラリ (DB, LINE client)
│   └── types/                # [Convention] 型定義
└── ...
```

*   **agents/**: AIプロンプトと型定義を集約。DBアクセスは含めず、純粋な入出力ロジックに徹する。
*   **app/(group)**: 用途ごとにディレクトリを分離し、将来のプラットフォーム拡張に備える。
*   **supabase/**: ルートに配置し、CLIツールの標準動作を保証する。

## 5. セキュリティ設計
*   **RLS (Row Level Security)**: DB層でアクセス権限を強制。アプリケーションコードのバグによるデータ漏洩を防ぐ。
*   **Environment Variables**: 機密情報（APIキー等）は `.env` ファイルで管理し、リポジトリには含めない。
*   **Secure Headers**: Next.jsの設定で適切なセキュリティヘッダーを付与。

## 6. パフォーマンス要件
*   **Core Web Vitals**: 良好なスコアを目指す（特にLCP, CLS）。
*   **Image Optimization**: Next.js ImageコンポーネントとSupabase Image Transformationを活用。
*   **Edge Caching**: VercelのEdge Networkを活用した静的アセットの配信。

## 7. LINE連携詳細

### 7.1 レポート送信方式

#### Webページ（メイン）
親御さんへの診断結果はWebページとして提供する。
- **URL**: `/report/[visitId]`
- **即時アクセス**: SSRにより、URLアクセス時点でDBからデータ取得→レンダリング
- **セキュリティ**: UUIDによる推測困難性（展示会の物理的管理下では十分）

#### LINE Flex Message
リッチカード形式でレポートURLを送信する。

```json
{
  "type": "flex",
  "altText": "太郎さんの診断レポート",
  "contents": {
    "type": "bubble",
    "header": { "イベント名・日付" },
    "body": {
      "お子様の名前・年齢",
      "担当スタッフ情報（名前・肩書き・アバター）"
    },
    "footer": {
      "「レポートを見る」ボタン → reportUrl"
    }
  }
}
```

#### 実装ファイル
- `src/lib/line.ts` - `createReportFlexMessage()` 関数
- `src/app/api/line/send-report/route.ts` - 送信API
- `src/app/report/[id]/page.tsx` - レポートWebページ

### 7.2 レポートWebページ表示項目
1. **ヘッダー**: イベント日付、イベント名、タイトル「分析シート」
2. **お子様情報**: 名前、年齢
3. **写真**: 姿勢（横・正面）、口腔内
4. **分析コメント**: AI生成コメント（スタッフ編集後）
5. **担当スタッフ**: 名前、肩書き、アバター
6. **フッター**: cOralupロゴ

## 8. 管理機能（問診・診断項目）

### 8.1 MVP対応
- **方式**: Supabase Dashboard から `form_schemas.schema_data` (JSONB) を直接編集
- **バージョン管理**: `form_schema_versions` テーブルで変更履歴を保持

### 8.2 Phase 2以降
- **管理画面UI**: `/admin/schemas/questionnaire`, `/admin/schemas/diagnosis`
- **機能**: ドラッグ&ドロップ並び替え、インライン編集、プレビュー、ロールバック

### 8.3 データ整合性
- **UUID識別**: 項目名変更しても、UUIDで紐付けられるため過去データ集計に影響なし
- **論理削除**: `is_active = false` で非アクティブ化（物理削除しない）
- **スキーマスナップショット**: 回答保存時に使用したスキーマバージョンを記録
