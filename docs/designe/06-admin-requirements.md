# Coralup 管理者用管理画面 詳細要件定義

## 1. システム概要

### 1.1 目的
管理者用管理画面は、Coralupシステム全体のデータを統合管理し、効率的な運営を支援する。親御さんユーザー、スタッフ、診断データ、イベント情報を一元管理し、BI機能によるデータ分析を可能にする。

### 1.2 対象ユーザー
- **システム管理者**: 全体のデータ管理、システム設定、ユーザー管理
- **運営責任者**: データ分析、イベント管理、レポート作成
- **データアナリスト**: 統計分析、トレンド分析、改善提案

### 1.3 システム要件
- レスポンシブデザイン（デスクトップ・タブレット対応）
- リアルタイムデータ同期
- 高度な検索・フィルタリング機能
- エクスポート機能（CSV, PDF, Excel）
- 権限制御機能

## 2. 機能要件詳細

### 2.1 ダッシュボード機能

#### 2.1.1 メインダッシュボード
- **KPI表示**
  - 今日の新規ユーザー数
  - 完了した診断数
  - アクティブセッション数
  - 平均診断時間

- **リアルタイム統計**
  - イベント別参加者数
  - 診断完了率
  - ユーザー満足度スコア
  - システム稼働状況

- **グラフ・チャート**
  - 診断結果分布（姿勢・口腔別）
  - 時間帯別アクセス状況
  - イベント参加推移
  - スタッフ別診断数

#### 2.1.2 カスタムダッシュボード
- ウィジェットのドラッグ&ドロップ配置
- 期間指定によるデータ絞り込み
- グラフの種類変更（棒グラフ、円グラフ、折れ線グラフ）
- ダッシュボードの保存・共有機能

### 2.2 ユーザー管理機能

#### 2.2.1 ユーザー一覧・検索
- **検索条件**
  - ユーザーID、名前、電話番号
  - 登録日時範囲指定
  - 最終診断日時
  - イベント参加履歴

- **表示項目**
  - ユーザー基本情報（名前、年齢、性別）
  - 連絡先情報（電話番号、LINE連携状況）
  - 診断履歴（診断回数、最終診断日）
  - ステータス（アクティブ/非アクティブ）

- **一括操作**
  - ユーザー一括削除
  - ステータス一括変更
  - CSVエクスポート

#### 2.2.2 ユーザーデータ統合管理
```sql
-- ユーザー統合ビュー
CREATE VIEW admin_user_view AS
SELECT
    u.id,
    u.session_id,
    u.created_at as session_created,
    q.child_name,
    q.child_age,
    q.child_gender,
    q.parent_name,
    q.parent_phone,
    d.diagnosis_date,
    d.posture_score,
    d.oral_score,
    r.report_sent_date,
    r.report_status
FROM sessions u
LEFT JOIN questionnaires q ON u.session_id = q.session_id
LEFT JOIN diagnoses d ON u.session_id = d.session_id
LEFT JOIN reports r ON u.session_id = r.session_id
```

#### 2.2.3 詳細ユーザー情報画面
- 基本情報タブ（問診票内容、保護者情報）
- 診断履歴タブ（過去の診断結果一覧）
- タイムラインタブ（セッション履歴）
- 編集機能（情報の修正・追加）

### 2.3 診断データ管理機能

#### 2.3.1 診断データ集計・分析
- **集計条件**
  - 期間指定（日付範囲、イベント指定）
  - スタッフ指定
  - 診断項目別
  - 年齢層別
  - 地域別

- **分析指標**
  - 診断完了率
  - 平均診断時間
  - 項目別異常率
  - 改善率推移

#### 2.3.2 データビジュアライゼーション
- **チャート種類**
  - ヒートマップ（診断項目別異常分布）
  - 散布図（姿勢スコア vs 口腔スコア）
  - 時系列グラフ（診断数推移）
  - 比較チャート（スタッフ別診断品質）

#### 2.3.3 データエクスポート
- CSVエクスポート（全データ・集計データ）
- PDFレポート生成
- Excel形式での出力
- グラフ画像のエクスポート

### 2.4 フォーム作成・管理機能

#### 2.4.1 フォームビルダー
- **ドラッグ&ドロップUI**
  - フォーム要素の配置（テキスト、選択肢、ラジオボタン、チェックボックス）
  - セクション分け機能
  - 条件分岐設定

- **フォーム要素タイプ**
  - テキスト入力（単一行・複数行）
  - 数値入力（年齢・スコア）
  - 選択肢（単一選択・複数選択）
  - 日付入力
  - ファイルアップロード
  - 評価スケール（1-10）

#### 2.4.2 フォーム管理
- **フォーム一覧**
  - フォーム名、作成日時、更新日時
  - 使用イベント、ステータス
  - 回答数、完了率

- **バージョン管理**
  - フォームのバージョン履歴
  - 差分表示機能
  - ロールバック機能

#### 2.4.3 イベント別フォーム管理
```sql
-- イベント別フォーム管理テーブル
CREATE TABLE event_forms (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    event_id VARCHAR(50) NOT NULL,
    form_type VARCHAR(20) NOT NULL, -- 'questionnaire' | 'diagnosis'
    form_name VARCHAR(200) NOT NULL,
    form_config JSONB NOT NULL, -- フォーム設定データ
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 2.5 イベント管理機能

#### 2.5.1 イベント情報管理
- イベント基本情報（名称、日時、場所、担当者）
- 参加スタッフ割り当て
- 使用フォーム設定
- イベントステータス管理

#### 2.5.2 イベントパフォーマンス分析
- 参加者数推移
- 診断完了率
- スタッフ別パフォーマンス
- ユーザー満足度分析

### 2.6 BI（ビジネスインテリジェンス）機能

#### 2.6.1 Lark Base連携
- **利点**: 既存ツール活用、迅速な実装可能
- **機能**: データ同期、ダッシュボード、自動レポート
- **実装方法**: REST API連携、リアルタイム同期

#### 2.6.2 自前BI機能
- **利点**: カスタマイズ性が高く、柔軟な分析可能
- **機能**: カスタムクエリ、リアルタイムダッシュボード、機械学習分析
- **実装方法**: Next.js + Chart.js + 統計ライブラリ

#### 2.6.3 推奨アプローチ
- **フェーズ1**: Lark Base連携で基本的なBI機能を実装
- **フェーズ2**: 利用状況に応じて自前BI機能を追加
- **ハイブリッド**: 両方を組み合わせた最適なソリューション

## 4. パフォーマンス要件

### 4.1 レスポンス時間
- 画面表示: 2秒以内
- 検索結果表示: 1秒以内
- データエクスポート: 5秒以内（データ量による）

### 4.2 同時接続対応
- 最大同時ユーザー数: 50人
- データ処理スループット: 100クエリ/秒

### 4.3 データ処理能力
- 大規模データ集計: 10万件以内
- リアルタイム処理: 1秒以内
