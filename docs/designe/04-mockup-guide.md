## 📍 アクセス方法

### 1. 開発サーバーの起動

まず、開発サーバーを起動してください：

```bash
pnpm dev
```

サーバーが起動すると、通常は `http://localhost:3000` でアクセスできます。
ポート番号は環境によって異なる場合があります。コンソールに表示されるURLを確認してください。

## 🎨 静的デモページ（デザイン確認用）

デザイン確認やUI検証のために、セッションIDを固定した静的ページを用意しています。これらのページは常に同じモックデータを表示するため、デザイン確認に最適です。

### デモページ一覧

**URL:** `http://localhost:3000/demo`

デモページの一覧と各ページへのリンクが表示されます。

### 親御さん向けデモページ

#### 問診票入力画面（デモ）
**URL:** `http://localhost:3000/parent/questionnaire/demo`

- セッションIDが `demo` に固定された静的ページ
- デザイン確認用に最適化
- モックデータが自動的に読み込まれます

#### 結果表示画面（デモ）
**URL:** `http://localhost:3000/parent/result/demo`

- 問診票送信完了後の結果表示画面
- QRコード表示も含まれます

### スタッフ向けデモページ

#### 統合診断ページ（デモ）⭐ **推奨**
**URL:** `http://localhost:3000/staff/diagnosis/demo`

**1つのページで全フロー完結:**
- QR読み取り・セッションID入力（セッションID未確定時）
- セッション情報確認（問診票確認）
- 写真撮影（カメラ機能も動作します）
- 診断項目入力
- 確認・修正
- AI分析
- レポート送信

**特徴:**
- ページ読み込みなしでステップ切り替え（UX最大化）
- URLハッシュでステップ状態を反映（例: `#step=photos`）
- どのステップにも自由に行き来可能
- 進捗バーで常に現在位置を表示

**注意:** 以下の個別ページは統合診断ページに統合されました（後方互換性のため残存）：
- `/staff/session/demo` → 統合診断ページの `#step=session` に統合
- `/staff/review/demo` → 統合診断ページの `#step=review` に統合
- `/staff/analysis/demo` → 統合診断ページの `#step=analysis` に統合
- `/staff/report/demo` → 統合診断ページの `#step=report` に統合

## 📊 静的ページと動的ページの違い

### 動的ページ（`[id]` ルート）

**URL例:** `http://localhost:3000/parent/questionnaire/SESSION001`

- **特徴:**
  - URLパラメータからセッションIDを取得
  - セッションIDに応じて異なるデータを表示可能
  - 実際の運用で使用される形式
- **用途:**
  - 実際のセッション管理
  - 複数のセッションを扱う場合
  - 本番環境での使用

### 静的ページ（`demo` ルート）

**URL例:** `http://localhost:3000/parent/questionnaire/demo`

- **特徴:**
  - セッションIDが `demo` に固定
  - 常に同じモックデータを表示
  - URLパラメータの解決が不要
- **用途:**
  - デザイン確認
  - UI/UX検証
  - クライアントへのデモ
  - スクリーンショット撮影

---

## 💡 静的ページにする意味とデメリット

### ✅ 静的ページにする意味（メリット）

1. **デザイン確認の容易さ**
   - URLが固定されているため、ブックマークや共有が簡単
   - デザイナーやクライアントが直接アクセスして確認可能

2. **開発効率の向上**
   - パラメータ解決のロジックが不要
   - エラーが発生しにくい
   - デバッグが容易

3. **安定した動作**
   - モックデータが固定されているため、予期しない動作が少ない
   - 404エラーが発生しない

4. **デモ・プレゼンに最適**
   - クライアントへのデモ時に安定して動作
   - スクリーンショット撮影が容易

5. **テストの簡素化**
   - E2Eテストやスナップショットテストが書きやすい
   - テストデータが固定されているため、再現性が高い

### ❌ 静的ページのデメリット

1. **データの固定化**
   - 常に同じモックデータしか表示できない
   - 複数のセッションを確認するには複数の静的ページが必要

2. **コードの重複**
   - 動的ページと静的ページでコードが重複する可能性
   - メンテナンスコストが増加する可能性

3. **実際の動作との乖離**
   - 実際の運用では動的ルートを使用するため、動作が異なる可能性
   - パラメータ解決のバグを見逃す可能性

4. **本番環境での不要性**
   - デモ用途のみのため、本番環境では不要
   - デプロイ時に除外する必要がある

### 🎯 推奨される使い分け

- **デザイン確認・UI検証:** 静的ページ（`/demo`）を使用
- **機能テスト・統合テスト:** 動的ページ（`/[id]`）を使用
- **クライアントデモ:** 静的ページ（`/demo`）を使用
- **本番環境:** 動的ページ（`/[id]`）のみをデプロイ

## 🧑‍⚕️ スタッフ向けモックアップ

### エントリーポイント（ダッシュボード）
**URL:** `http://localhost:3000/staff`

ダッシュボードが表示されます。統計情報とクイックアクションが表示されます。

### 統合診断ページ（全フロー完結）
**URL:** `http://localhost:3000/staff/diagnosis` または `http://localhost:3000/staff/diagnosis/[セッションID]`

**デモ用URL:**
- `http://localhost:3000/staff/diagnosis/demo`

**実際のURL例:**
- `http://localhost:3000/staff/diagnosis` （セッションID未確定時）
- `http://localhost:3000/staff/diagnosis/demo` （デモ用）
- `http://localhost:3000/staff/diagnosis/SESSION001` （実際のセッション）

**特徴:**
- **1つのページで全フロー完結**: ページ読み込みなしでステップ切り替え
- **URLハッシュでステップ状態を反映**: 例: `#step=photos`
- **どのステップにも自由に行き来可能**
- **進捗バーで常に現在位置を表示**
- **コンポーネント分割**: 保守性・開発効率・パフォーマンスを最適化（詳細は [17-diagnosis-component-split-implementation-guide.md](./17-diagnosis-component-split-implementation-guide.md) を参照）

**このページで完結する全ステップ:**

1. **ステップ0: QR読み取り・セッションID入力**（セッションID未確定時のみ）
   - QRコード読み取り機能
   - セッションID直接入力
   - セッションID確定後、次のステップへ自動遷移

2. **ステップ1: セッション情報確認**（`#step=session`）
   - 親御さんが入力した問診票内容を確認
   - セッション情報の表示

3. **ステップ2: 写真撮影**（`#step=photos`）
   - 横向き姿勢、正面姿勢、口腔内写真を撮影
   - カメラ機能が動作します（ブラウザの許可が必要）
   - 撮影済み写真の確認・再撮影

4. **ステップ3: 診断項目入力**（`#step=diagnosis`）
   - 姿勢評価、口腔機能評価などの診断項目を入力
   - カテゴリごとに分かれて表示
   - カテゴリ間の自由な移動

5. **ステップ4: 確認・修正**（`#step=review`）
   - 入力した診断項目を一覧で確認
   - 撮影した写真を確認
   - どのステップにも戻って修正可能

6. **ステップ5: AI分析**（`#step=analysis`）
   - AI分析ボタンをタップして分析を実行
   - 分析結果を確認
   - レポート生成
   - レポート内容の修正・確認

7. **ステップ6: レポート送信**（`#step=report`）
   - 最終レポートの確認
   - LINE送信ボタンで親御さんにレポート通知

**ナビゲーション:**
- ステップインジケーターで現在位置と完了状況を表示
- 前へ/次へボタンでステップ間を移動
- 各ステップタブをタップして直接ジャンプ可能
- URLハッシュでステップ状態を共有・ブックマーク可能

## 🔄 フロー全体の確認方法

### スタッフ側のフロー（推奨順序）

**統合診断ページを使用したフロー（推奨）:**

1. **ダッシュボード**
   ```
   http://localhost:3000/staff
   ```
   → 「診断開始」ボタンをクリック

2. **統合診断ページ（QR読み取り・セッションID入力）**
   ```
   http://localhost:3000/staff/diagnosis
   ```
   → QRコード読み取りまたはセッションID直接入力

3. **統合診断ページ（セッション情報確認）**
   ```
   http://localhost:3000/staff/diagnosis/demo#step=session
   ```
   → 問診票内容を確認 → ステップタブで「写真」をタップ

4. **統合診断ページ（写真撮影）**
   ```
   http://localhost:3000/staff/diagnosis/demo#step=photos
   ```
   → 写真撮影 → ステップタブで「診断」をタップ

5. **統合診断ページ（診断項目入力）**
   ```
   http://localhost:3000/staff/diagnosis/demo#step=diagnosis
   ```
   → 診断項目入力 → ステップタブで「確認」をタップ

6. **統合診断ページ（確認・修正）**
   ```
   http://localhost:3000/staff/diagnosis/demo#step=review
   ```
   → 内容確認 → 必要に応じて修正 → ステップタブで「AI分析」をタップ

7. **統合診断ページ（AI分析）**
   ```
   http://localhost:3000/staff/diagnosis/demo#step=analysis
   ```
   → AI分析実行 → レポート生成 → ステップタブで「レポート送信」をタップ

8. **統合診断ページ（レポート送信）**
   ```
   http://localhost:3000/staff/diagnosis/demo#step=report
   ```
   → レポート確認 → LINE送信

**注意:** すべてのステップが1つのページ（`/staff/diagnosis/demo`）内で完結し、ページ読み込みなしで切り替え可能です。

## 📝 モックデータについて

現在の実装では、以下のモックデータが使用されています：

### セッションデータ
- セッションID: `SESSION001`, `SESSION002`
- お子様名: `お子様 花子`
- 保護者名: `保護者 太郎`
- 年齢: `8歳`

### 問診票データ
- 現在の悩み: `歯並びが気になる`, `口呼吸をしている`
- 理想とする状態: `きれいな歯並びになりたい`, `正しい姿勢を身につけたい`
- 既往歴: `アレルギー`

### 診断データ
- 姿勢評価: 頭部位置（正常）、肩バランス（左右差あり）など
- 口腔機能評価: 咬合状態（開咬）、歯並び（叢生）など

## 🔧 トラブルシューティング

### 404エラーが発生する場合

デモページにアクセスした際に404エラーが発生する場合は、以下の手順を試してください：

#### 1. ビルドキャッシュのクリアと再起動（推奨）

```bash
# 開発サーバーを停止（Ctrl+C）

# ビルドキャッシュを削除
rm -rf .next

# 開発サーバーを再起動
pnpm dev
```

**理由**: Next.jsはビルド時にルーティング情報をキャッシュするため、新しいルートを追加した場合はキャッシュをクリアする必要があります。

#### 2. ポート番号の確認

開発サーバーが起動しているポート番号を確認してください。デフォルトでは`3000`ポートで起動します：

```bash
# package.jsonで確認
# "dev": "next dev"
```

正しいURL例：
- `http://localhost:3000/demo`
- `http://localhost:3000/parent/questionnaire/demo`

#### 3. ファイル構造の確認

以下のファイルが存在することを確認してください：

```bash
# ファイルの存在確認
ls -la src/app/(parent)/questionnaire/demo/page.tsx
ls -la src/app/(parent)/result/demo/page.tsx
ls -la src/app/(staff)/session/demo/page.tsx
ls -la src/app/(staff)/diagnosis/demo/page.tsx
ls -la src/app/(staff)/review/demo/page.tsx
ls -la src/app/(staff)/analysis/demo/page.tsx
ls -la src/app/(staff)/report/demo/page.tsx
ls -la src/app/demo/page.tsx
```

#### 4. ブラウザのキャッシュクリア

ブラウザのキャッシュが原因の場合があります：

- **Chrome/Edge**: `Ctrl+Shift+Delete`（Windows）または `Cmd+Shift+Delete`（Mac）
- **Firefox**: `Ctrl+Shift+Delete`（Windows）または `Cmd+Shift+Delete`（Mac）
- **Safari**: `Cmd+Option+E`

または、シークレットモード/プライベートモードでアクセスしてみてください。

#### 5. 開発サーバーのログ確認

開発サーバーのコンソールにエラーメッセージが表示されていないか確認してください。

### よくある問題と解決策

#### 問題: `/demo`ページが404になる

**解決策**: 
1. ビルドキャッシュをクリア（上記手順1を参照）
2. 開発サーバーを再起動
3. `http://localhost:3000/demo`にアクセス

#### 問題: `/parent/questionnaire/demo`が動的ルート`[id]`として認識される

**解決策**: 
Next.js App Routerでは静的ルートが動的ルートより優先されるはずですが、ビルドキャッシュの問題で発生する場合があります。上記手順1を実行してください。

#### 問題: カメラが起動しない

**解決策**:
1. ブラウザのカメラアクセス許可を確認
2. HTTPSまたはlocalhostでアクセスしていることを確認（HTTPではカメラAPIが動作しない場合があります）
3. ブラウザの設定でカメラアクセスを許可
