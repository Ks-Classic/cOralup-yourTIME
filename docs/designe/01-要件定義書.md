# Coralup 要件定義書

## 1. プロジェクト概要

### 1.1 背景
Coralupは、口腔育成のためのセミナーやトレーナー育成事業を展開しており、顧客（親御さん）とトレーナー（歯科衛生士）のマッチングプラットフォームを目指しています。

### 1.2 目的
- イベントでの診断効率化のための問診票デジタル化
- 姿勢・口腔写真のAI分析による診断支援
- LINEでの自動通知による顧客体験向上
- ユーザーDBへの自動登録による顧客管理の効率化

### 1.3 対象ユーザー
- **親御さん**: お子様の口腔・姿勢状態の診断を希望する保護者
- **スタッフ**: 診断業務を担当する歯科衛生士・トレーナー
- **管理者**: システム全体の管理とデータ分析を行う運営者

## 2. 機能要件

### 2.1 親御さん向け機能

#### 2.1.1 問診票入力
- お子様の基本情報入力（氏名、年齢、性別）
- 既往歴の選択式入力
- 現在の悩みや気になる点の選択式入力
- 理想とする状態の選択式入力
- スタッフへの申し送り事項の自由記述
- 写真撮影の同意確認

#### 2.1.2 LINE連携
- LINE友だち登録後の診断ボタンタップによる問診票ページへの遷移
- セッションIDの発行とLINE通知
- 診断結果の自動受信
- フォローアップ情報の提供

**LINE連携フロー:**
1. 親御さんが紙のQRコードをLINEで読み込み
2. LINE友だち登録
3. LINE画面で診断ボタンをタップ
4. 問診票ページへ遷移
5. 問診票入力完了後、QRコード表示（親御さん）
6. 診断完了後、スタッフがLINE送信ボタンをタップ
7. 親御さんのLINEにレポート通知が送信される

#### 2.1.3 診断結果確認
- PDFレポートの自動受信
- 次のステップの案内
- 追加相談の申し込み機能

### 2.2 スタッフ向け機能

#### 2.2.1 セッション管理
- 親御さんが表示したQRコードをスタッフが読み込む
- 親御さん入力内容（名前や問診票）の確認画面表示
- リアルタイムな問診票データの参照
- セッション状態の管理（開始・診断中・完了）

#### 2.2.2 診断機能
- **診断開始で実際にお子さんの測定しながら、結果をスマホに入力**
- 姿勢写真の撮影・管理（正面・横向き）
- 口腔内写真の撮影・管理（カメラで撮影）
- 診断項目ごとのチェックボックス入力（測定しながら入力）
- メモ・所見の記録機能
- チェック内容・写真確認機能

#### 2.2.3 レポート生成
- AI分析ボタンによる分析実行
- AI分析結果の確認
- レポート生成
- レポート内容の修正・確認
- PDF生成とLINE送信（ボタンタップで親御さんLINEにレポート通知）

### 2.3 AI診断機能

#### 2.3.1 姿勢分析
- 写真からの姿勢評価
- 骨格・筋肉の状態分析
- 改善点の提案

#### 2.3.2 口腔分析
- 口腔内写真の分析
- 咬合・歯並びの評価
- 口腔機能の評価

#### 2.3.3 レポート生成
- 診断結果の統合分析
- 個人に合わせたアドバイス生成
- PDFレポートの自動作成

### 2.4 データ管理機能

#### 2.4.1 ユーザー管理
- 親御さん情報の自動登録
- スタッフ情報の管理
- 管理者権限の設定

#### 2.4.2 データ分析
- 診断データの統計分析
- 傾向分析とレポート
- Lark Base連携による可視化

#### 2.4.3 システム管理
- ユーザーセッションの管理
- データバックアップ
- ログ管理

## 3. 非機能要件

### 3.1 性能要件
- レスポンスタイム: 3秒以内
- 同時接続数: 100セッション以上
- データ処理速度: 写真1枚あたり5秒以内

### 3.2 セキュリティ要件
- データ暗号化（SSL/TLS）
- 個人情報保護法準拠
- アクセス制御の実装
- 定期的なセキュリティ監査

### 3.3 可用性要件
- 稼働率: 99.5%以上
- バックアップ頻度: 1日1回
- 障害復旧時間: 4時間以内

### 3.4 ユーザビリティ要件
- 直感的な操作性
- レスポンシブデザイン
- アクセシビリティ対応（WCAG 2.1準拠）

## 4. 制約条件

### 4.1 技術的制約
- ブラウザ対応: 最新版Chrome, Safari, Edge
- モバイル対応: iOS 12+, Android 8+
- カメラ機能必須（写真撮影のため）

### 4.2 運用制約
- オフライン環境での使用不可
- インターネット接続必須
- イベント会場でのWi-Fi環境必須

## 5. 優先度とリリース計画

### Phase 1: MVP（Minimum Viable Product）
- 基本的な問診票機能
- スタッフ向け診断機能
- 基本的なレポート生成

### Phase 2: 機能拡張
- AI分析機能の追加
- LINE連携の実装
- データ分析機能の追加

### Phase 3: 最適化
- 性能最適化
- UI/UX改善
- 追加機能の実装
