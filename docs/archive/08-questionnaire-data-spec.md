# 問診票データ構造仕様書

## 概要

### 目的と用途

本ドキュメントは、cOralupシステムにおける問診票データ構造の完全な仕様を定義します。

- **目的**: 問診票フォームのデータ構造、フィールド定義、バリデーションルール、条件付き表示ロジックを明確化
- **用途**: 
  - フロントエンド実装の参照
  - バックエンドAPI設計の参照
  - データベーススキーマ設計の参照
  - データ分析・集計処理の参照

### データ形式の説明

問診票データは、**JSON Schema形式**で定義されたTypeScript型定義に基づいて管理されます。

- **スキーマ定義**: `FormSchemaConfig`型を使用
- **フィールド定義**: `FormFieldConfig`型を使用
- **型定義ファイル**: `src/types/forms.ts`

## 未就学児用問診票の仕様

### 全セクションのリスト

未就学児用問診票は、以下の9つのセクションで構成されています：

1. **基本情報** (`basic_info`) - 順序: 1
2. **きょうだい** (`siblings`) - 順序: 2
3. **スマホ・タブレット・TV視聴** (`screen_time`) - 順序: 3
4. **睡眠の様子** (`sleep`) - 順序: 4
5. **睡眠時間** (`sleep_time`) - 順序: 5
6. **習い事** (`lessons`) - 順序: 6
7. **食事について** (`eating`) - 順序: 7
8. **食べ物の好み** (`food_preferences`) - 順序: 8
9. **同意事項** (`consent`) - 順序: 9

> **注意**: 生年月日と性別は、基本情報入力画面で別途入力されます。フォームスキーマには含まれていません。

### セクション1: 基本情報

**セクションID**: `basic_info`  
**タイトル**: 基本情報  
**説明**: お子様の基本情報を入力してください  
**順序**: 1

#### 項目リスト

| 項目ID | 項目名 | フィールドタイプ | 必須 | 説明 |
|--------|--------|------------------|------|------|
| `furigana` | ふりがな | `text` | 任意 | お名前のふりがな |
| `child_name` | お名前 | `text` | 必須 | お子様のお名前 |
| `prefecture` | 都道府県 | `select` | 任意 | 都道府県の選択 |
| `nickname` | ニックネーム | `text` | 任意 | お子様のニックネーム |

#### フィールドタイプ定義

**`furigana` (ふりがな)**
- **タイプ**: `text`
- **必須**: `false`
- **プレースホルダー**: `"例: たなか たろう"`
- **バリデーション**: なし

**`child_name` (お名前)**
- **タイプ**: `text`
- **必須**: `true`
- **プレースホルダー**: `"例: 田中 太郎"`
- **バリデーション**:
  - `minLength`: 1
  - `maxLength`: 100

**`prefecture` (都道府県)**
- **タイプ**: `select`
- **必須**: `false`
- **プレースホルダー**: `"都道府県を選択してください"`
- **オプション**: `prefectures`配列（47都道府県）
- **バリデーション**: なし

**`nickname` (ニックネーム)**
- **タイプ**: `text`
- **必須**: `false`
- **プレースホルダー**: `"例: たーくん"`
- **バリデーション**:
  - `maxLength`: 50

### セクション2: きょうだい

**セクションID**: `siblings`  
**タイトル**: きょうだい  
**説明**: きょうだいの有無を教えてください  
**順序**: 2

#### 項目リスト

| 項目ID | 項目名 | フィールドタイプ | 必須 | 説明 |
|--------|--------|------------------|------|------|
| `has_siblings` | きょうだい | `radio` | 必須 | きょうだいの有無 |
| `sibling_order` | 何人目 | `number` | 条件付き必須 | きょうだいがいる場合のみ |

#### フィールドタイプ定義

**`has_siblings` (きょうだい)**
- **タイプ**: `radio`
- **必須**: `true`
- **オプション**:
  - `{ value: 'none', label: 'いない' }`
  - `{ value: 'has', label: 'いる' }`
- **バリデーション**: 必須選択

**`sibling_order` (何人目)**
- **タイプ**: `number`
- **必須**: `false`（条件付き必須）
- **プレースホルダー**: `"例: 1"`
- **ヘルパーテキスト**: `"きょうだいがいる場合のみ入力してください"`
- **バリデーション**:
  - `min`: 1
  - `max`: 10
- **条件付き表示**: `has_siblings === 'has'`の場合のみ表示

### セクション3: スマホ・タブレット・TV視聴

**セクションID**: `screen_time`  
**タイトル**: スマホ・タブレット・TV視聴  
**説明**: 1日の視聴時間を教えてください  
**順序**: 3

| 項目ID | 項目名 | フィールドタイプ | 必須 | 説明 |
|--------|--------|------------------|------|------|

| `screen_hours` | 時間数 | `number` | 条件付き | 「○時間以内」選択時のみ |
| `screen_more_hours` | それ以上の時間数 | `number` | 条件付き | 「それ以上」選択時のみ |

#### フィールドタイプ定義

**`screen_time` (視聴頻度と時間)**
- **タイプ**: `radio`
- **必須**: `true`
- **オプション**:

  - `{ value: 'more', label: 'それ以上' }`
- **バリデーション**: 必須選択

**`screen_hours` (時間数)**
- **タイプ**: `number`
- **必須**: `false`（条件付き）
- **プレースホルダー**: `"例: 2"`
- **ヘルパーテキスト**: `"「○時間以内」を選択した場合のみ入力してください"`
- **バリデーション**:
  - `min`: 0
  - `max`: 24
- **条件付き表示**: `screen_time === 'within_hours'`の場合のみ表示

**`screen_more_hours` (それ以上の時間数)**

- **必須**: `false`（条件付き）
- **プレースホルダー**: `"例: 3"`

## 共通仕様

### FormSchemaConfig 型定義の説明

`FormSchemaConfig`は、問診票フォーム全体の構造を定義する型です。

```typescript
export type FormSchemaConfig = {
  sections: FormSectionConfig[]
  settings?: FormSettings
  metadata?: Record<string, any>
}
```

#### プロパティ説明

- **`sections`** (必須): フォームのセクション配列
- **`settings`** (任意): フォームの設定（進捗表示、戻るナビゲーション等）
- **`metadata`** (任意): 追加のメタデータ

### FormSectionConfig 型定義の説明

`FormSectionConfig`は、フォームの各セクションを定義する型です。

```typescript
export type FormSectionConfig = {
  id: string
  title: string
  description?: string
  order?: number
  fields: FormFieldConfig[]
}
```

#### プロパティ説明

- **`id`** (必須): セクションの一意識別子
- **`title`** (必須): セクションのタイトル
- **`description`** (任意): セクションの説明文
- **`order`** (任意): セクションの表示順序
- **`fields`** (必須): セクション内のフィールド配列

### FormFieldConfig 型定義の説明

`FormFieldConfig`は、フォームの各フィールドを定義する型です。

```typescript
export type FormFieldConfig = {
  id: string
  name: string
  type: FormFieldType
  required?: boolean
  placeholder?: string
  helperText?: string
  options?: FormFieldOption[]
  defaultValue?: string | number | boolean | (string | number | boolean)[]
  validation?: FormFieldValidation
  rows?: number
  min?: number
  max?: number
  step?: number
}
```

#### プロパティ説明

- **`id`** (必須): フィールドの一意識別子
- **`name`** (必須): フィールドの表示名
- **`type`** (必須): フィールドタイプ（後述）
- **`required`** (任意): 必須フラグ（デフォルト: `false`）
- **`placeholder`** (任意): プレースホルダーテキスト
- **`helperText`** (任意): ヘルパーテキスト（入力支援用）
- **`options`** (任意): 選択肢配列（`select`、`radio`、`checkbox`用）
- **`defaultValue`** (任意): デフォルト値
- **`validation`** (任意): バリデーションルール
- **`rows`** (任意): テキストエリアの行数
- **`min`** (任意): 数値の最小値
- **`max`** (任意): 数値の最大値
- **`step`** (任意): 数値のステップ値

### バリデーションルールの定義方法

バリデーションルールは、`FormFieldValidation`型で定義されます。

```typescript
export type FormFieldValidation = {
  min?: number
  max?: number
  minLength?: number
  maxLength?: number
  pattern?: string
  patternMessage?: string
}
```

#### バリデーションルールの説明

- **`min`**: 数値の最小値（`number`型フィールド用）
- **`max`**: 数値の最大値（`number`型フィールド用）
- **`minLength`**: 文字列の最小長（`text`、`textarea`型フィールド用）
- **`maxLength`**: 文字列の最大長（`text`、`textarea`型フィールド用）
- **`pattern`**: 正規表現パターン（文字列検証用）
- **`patternMessage`**: パターンマッチ失敗時のエラーメッセージ

#### バリデーション例

```typescript
// テキストフィールドのバリデーション
{
  id: 'child_name',
  name: 'お名前',
  type: 'text',
  required: true,
  validation: {
    minLength: 1,
    maxLength: 100
  }
}

// 数値フィールドのバリデーション
{
  id: 'bedtime',
  name: '就寝時刻',
  type: 'number',
  required: false,
  validation: {
    min: 0,
    max: 23
  }
}
```

### 条件付き表示ロジックの定義方法

条件付き表示は、現在の実装では**フィールドの`required`プロパティと`helperText`で示唆**されていますが、**明示的な条件定義はフォームスキーマには含まれていません**。

実際の条件付き表示ロジックは、フロントエンドコンポーネント（`DynamicForm`）で実装されています。

#### 条件付き表示のパターン

1. **ラジオボタン選択による条件表示**
   - 例: `has_siblings === 'has'`の場合のみ`sibling_order`を表示
   - 例: `screen_time === 'within_hours'`の場合のみ`screen_hours`を表示

2. **チェックボックス選択による条件表示**
   - 例: `sleep_conditions`に`'other'`が含まれる場合のみ`sleep_other`を表示
   - 例: `eating_habits`に`'other'`が含まれる場合のみ`eating_other`を表示

#### 実装上の注意点

- 条件付き表示ロジックは、フロントエンドコンポーネントで実装する必要があります
- 将来的には、スキーマに条件定義を追加することを検討してください

## スタッフ診断項目の仕様

### 概要

スタッフが診断時に入力する診断評価項目の仕様を定義します。これらの項目は、親御さんが入力する問診票とは別に、スタッフが実際の診断時に測定・評価しながら入力します。

### データ構造

スタッフ診断項目は、`DiagnosisItem`型で定義され、`src/data/staff-diagnosis-items.ts`に定義されています。

#### DiagnosisItem型の定義

```typescript
export interface DiagnosisItem {
  id: string                    // 項目の一意なID
  category: string              // カテゴリ名（例: '舌', '歯列・咬合'）
  subCategory: string           // サブカテゴリ名（通常はcategoryと同じ）
  question: string              // 質問文
  answerType: 'checkbox' | 'radio' | 'text' | 'number' | 'textarea'
  options?: { value: string; label: string }[]  // 選択肢（checkbox/radioの場合）
  required: boolean             // 必須項目かどうか
  inputType: 'parent' | 'staff' // 入力者タイプ
  analysisUse?: boolean         // 分析に利用するかどうか
  note?: string                 // 補足説明
  placeholder?: string          // プレースホルダー
  unit?: string                 // 単位（numberの場合、例: 'kg'）
  min?: number                  // 最小値（numberの場合）
  max?: number                  // 最大値（numberの場合）
}
```

### UI設計

#### 画面構成

スタッフ診断入力画面は、以下の5つのビューで構成されます：

1. **問診** - 親御さんが入力した問診票の確認
2. **写真** - 診断用写真の撮影・管理
3. **診断** - スタッフが入力する診断項目（カテゴリタブ付き）
4. **確認/分析** - 診断内容の確認とAI分析
5. **レポート** - レポート生成・送信

#### 下部ナビゲーションメニュー

画面下部に固定されたナビゲーションメニューで、5つのビューを切り替えます：

```
┌─────────────────────────────────────────┐
│  [問診] [写真] [診断] [確認/分析] [レポート] │
└─────────────────────────────────────────┘
```

各メニュー項目には：
- アイコン表示
- 完了状態のインジケーター（緑のドット）
- アクティブ状態のハイライト

#### 診断ビュー（カテゴリタブ付き）

診断ビューでは、カテゴリごとにタブで切り替えながら診断項目を入力します：

```
┌─────────────────────────────────────────┐
│  診断入力進捗: 45%                      │
│  ████████████░░░░░░░░                   │
├─────────────────────────────────────────┤
│  [舌] [歯列・咬合] [口唇] [鼻・扁桃] ... │
│  ─────────────────────────────────────  │
│                                         │
│  舌小帯短縮症 *                         │
│  ○ 有  ○ 無                            │
│                                         │
│  ハート舌 *                             │
│  ○ 有  ○ 無                            │
│                                         │
└─────────────────────────────────────────┘
```

カテゴリタブの特徴：
- 横スクロール可能
- 完了したカテゴリにはチェックマーク表示
- 入力中のカテゴリには進捗バッジ表示（例: 3/8）
- アクティブなタブはハイライト表示

### データ保存形式

スタッフ診断項目の回答データは、以下の形式で保存されます：

```typescript
{
  // 診断項目の回答
  diagnosisValues: {
    [itemId: string]: string | number | string[] | null
  },
  
  // スタッフメモ
  staffNotes: string,
  
  // 写真データ
  photos: PhotoData[],
  
  // セッション情報
  sessionId: string,
  childName: string,
  childAge: number,
  childGender: string,
}
```
